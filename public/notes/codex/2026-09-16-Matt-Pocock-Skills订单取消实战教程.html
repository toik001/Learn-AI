Matt Pocock Skills 订单取消实战教程

总览 · 安装与环境 · 完整实战 · 原理说明

第 2 课：在已有订单项目中增加取消能力，用同一条产物链串起访谈、规格、任务、TDD、审查与交付。预计 2～4 小时，可分两次会话。

证据边界：页面中的提示词、示范规格和任务是教学设计，不是 Agent 会话实录。基础版测试、单个预期失败测试、完成版测试与打包均已通过真实命令核验，结果见第 9 节；这些验证不代表已经测量整套 Agent 工作流的成功率。

核心结论

本课成功的标准是：一个新会话只读取任务和领域资料，也能理解要实现什么，并用接口结果证明它完成了。你负责业务决策，Agent 查事实、实现、验证并呈现证据。

先完成上一课，保留 workshop-ready 标签。完整答案用于对照，先按主线练习；不要在自己正在修改的项目上覆盖答案。

1. 先给出业务目标，逐轮解决分歧

把已确认的术语写入 CONTEXT.md，符合条件的重要取舍才写 ADR。
这一阶段先把需求说清楚。

Agent 应发现系统已有 UNPAID、PAID、CANCELLED 三个数据库状态；已有登录、所有权过滤、版本字段和付款行锁。状态枚举已经存在并不表示取消功能已实现。随后访谈聚焦业务决定。

决策本课选定答案对实现的影响
谁能取消登录的订单所有者身份取自 Principal，不接受请求传入 owner
哪些状态UNPAID 可取消；PAID 拒绝成功 200，非法状态 409
重复取消对已经 CANCELLED 的订单返回现状不再递增 version
不存在或他人订单统一 404不通过差异透露订单归属
支付与取消竞态数据库串行化状态转移，先取得锁并完成合法迁移者成功另一动作 409；version 只增加一次
取消是否退款本课不退款，支付为本地模拟没有外部支付副作用、事件总线或退款流程
界面与保护页面提供按钮，后端保留鉴权、所有权与 CSRF按钮禁用仅是交互提示，服务端仍独立判断

这张表是可直接采用的教学决策，不是假设所有业务都应如此。真实项目若存在发货、部分取消或支付网关回调，需要重新访谈。阶段完成条件：没有遗漏的关键业务决定，并且你确认这些决定。

6. 用反馈推动实现，而不是一次补齐想象中的代码

一个合理实现会复用已存在的订单锁与状态迁移逻辑：先在事务中按 id 和 owner 查询并锁住行；如果已经是目标状态，直接返回；如果不是 UNPAID，报告冲突；否则更新状态并递增 version。外部 HTTP 请求通过 Spring 管理的 Bean 调用 @Transactional 方法。

注意 Spring 的代理事务边界：本例 cancel 与 pay 都是 Controller 从外部调用的 public 方法；不要把事务注解仅放在被同类内部调用的私有方法上。

7. 审查前先明确 diff 覆盖范围

固定提交中的 implement 要求审查后提交，而 code-review 默认使用三点式已提交 diff。两者直接照搬可能漏掉刚写的代码。本课在练习仓库的 AGENTS.md 显式适配：提交前审查 HEAD 到当前工作区的所有改动，并读取新增文件。这是课程适配，不是声称上游原版已经处理。

示例 / 命令
git status --short
git diff HEAD --stat
git diff HEAD
git ls-files --others --exclude-standard

git diff HEAD 包含暂存与未暂存的已跟踪文件；最后一条列出它不包含的新增文件，审查时还要逐一读内容。不要把“diff 为空”直接解释为无问题。

package study.orders;

import java.util.List;
import org.springframework.http.HttpStatus;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.jdbc.core.RowMapper;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import org.springframework.web.server.ResponseStatusException;

@Service
public class OrderService {
    private final JdbcTemplate jdbc;
    private static final RowMapper<OrderView> ROW = (rs, row) -> new OrderView(
        rs.getLong("id"), rs.getString("owner"), rs.getString("status"), rs.getLong("version"));

    public OrderService(JdbcTemplate jdbc) { this.jdbc = jdbc; }

    public List<OrderView> list(String owner) {
        return jdbc.query("SELECT * FROM customer_order WHERE owner = ? ORDER BY id", ROW, owner);
    }

    public OrderView get(long id, String owner) { return find(id, owner, false); }

    @Transactional
    public OrderView pay(long id, String owner) { return transition(id, owner, "PAID"); }

    @Transactional
    public OrderView cancel(long id, String owner) { return transition(id, owner, "CANCELLED"); }

    private OrderView transition(long id, String owner, String target) {
        OrderView current = find(id, owner, true);
        if (current.status().equals(target)) return current;
        if (!current.status().equals("UNPAID")) {
            throw new ResponseStatusException(HttpStatus.CONFLICT, "STATE_CONFLICT");
        }
        jdbc.update("UPDATE customer_order SET status = ?, version = version + 1 WHERE id = ? AND owner = ?",
            target, id, owner);
        return find(id, owner, false);
    }

    private OrderView find(long id, String owner, boolean lock) {
        List<OrderView> found = jdbc.query(
            "SELECT * FROM customer_order WHERE id = ? AND owner = ?" + (lock ? " FOR UPDATE" : ""),
            ROW, id, owner);
        if (found.isEmpty()) throw new ResponseStatusException(HttpStatus.NOT_FOUND, "ORDER_NOT_FOUND");
        return found.getFirst();
    }
}

package study.orders;

import java.security.Principal;
import java.util.List;
import java.util.Map;
import org.springframework.security.web.csrf.CsrfToken;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class OrderController {
    private final OrderService orders;
    public OrderController(OrderService orders) { this.orders = orders; }

    @GetMapping("/api/csrf")
    Map<String, String> csrf(CsrfToken token) {
        return Map.of("headerName", token.getHeaderName(), "token", token.getToken());
    }

    @GetMapping("/api/orders")
    List<OrderView> list(Principal user) { return orders.list(user.getName()); }

    @GetMapping("/api/orders/{id}")
    OrderView get(@PathVariable long id, Principal user) { return orders.get(id, user.getName()); }

    @PostMapping("/api/orders/{id}/cancel")
    OrderView cancel(@PathVariable long id, Principal user) { return orders.cancel(id, user.getName()); }

    @PostMapping("/api/orders/{id}/pay")
    OrderView pay(@PathVariable long id, Principal user) { return orders.pay(id, user.getName()); }
}

const message = document.getElementById('message');
let csrf;
async function request(url, method = 'GET') {
  const response = await fetch(url, {
    method,
    headers: method === 'GET' ? {} : { [csrf.headerName]: csrf.token },
    credentials: 'same-origin'
  });
  if (response.redirected || response.status === 401) {
    location.assign('/login');
    throw new Error('请重新登录');
  }
  if (!response.ok) throw new Error(`请求失败：HTTP ${response.status}`);
  return response.status === 204 ? null : response.json();
}
async function loadOrders() {
  const orders = await request('/api/orders');
  const body = document.getElementById('orders');
  body.replaceChildren();
  for (const order of orders) {
    const row = document.createElement('tr');
    for (const value of [order.id, order.owner, order.status, order.version]) {
      const cell = document.createElement('td');
      cell.textContent = String(value);
      row.append(cell);
    }
    const actions = document.createElement('td');
    addAction(actions, order, 'pay', '模拟支付', order.status === 'UNPAID');
    addAction(actions, order, 'cancel', '取消订单', ['UNPAID', 'CANCELLED'].includes(order.status));
    row.append(actions);
    body.append(row);
  }
}
function addAction(cell, order, action, label, enabled) {
  const button = document.createElement('button');
  button.textContent = label;
  button.disabled = !enabled;
  button.addEventListener('click', async () => {
    button.disabled = true;

      message.textContent = `订单 ${result.id}：${result.status}，版本 ${result.version}`;
    } catch (error) { message.textContent = error.message; }
    finally { await loadOrders().catch(error => { message.textContent = error.message; }); }
  });
  cell.append(button);
}

    @Test void cannotPayAfterCancellation() throws Exception {
        assertThat(send(alice, "POST", "/api/orders/101/cancel").statusCode()).isEqualTo(200);
        assertThat(send(alice, "POST", "/api/orders/101/pay").statusCode()).isEqualTo(409);
        assertThat(statusOf(alice, 101)).isEqualTo("CANCELLED");
        assertThat(versionOf(alice, 101)).isEqualTo(1);
    }

    @Test void concurrentCancellationsAreIdempotent() throws Exception {
        assertThat(race("cancel", "cancel")).containsExactlyInAnyOrder(200, 200);
        assertThat(statusOf(alice, 101)).isEqualTo("CANCELLED");
        assertThat(versionOf(alice, 101)).isEqualTo(1);
    }

    @RepeatedTest(5) void paymentAndCancellationHaveOneWinner() throws Exception {
        assertThat(race("pay", "cancel")).containsExactlyInAnyOrder(200, 409);
        assertThat(statusOf(alice, 101)).isIn("PAID", "CANCELLED");
        assertThat(versionOf(alice, 101)).isEqualTo(1);
    }

    private List<Integer> race(String first, String second) throws Exception {
        // Separate authenticated sessions allow two real HTTP requests to race.
        Actor otherSession = actor("alice", "alice-test-only");
        CountDownLatch ready = new CountDownLatch(2);
        CountDownLatch start = new CountDownLatch(1);
        try (var pool = Executors.newVirtualThreadPerTaskExecutor()) {
            var a = pool.submit(() -> {
                ready.countDown();
                if (!start.await(5, TimeUnit.SECONDS)) throw new IllegalStateException("start timeout");
                return send(alice, "POST", "/api/orders/101/" + first).statusCode();
            });
            var b = pool.submit(() -> {
                ready.countDown();
                if (!start.await(5, TimeUnit.SECONDS)) throw new IllegalStateException("start timeout");
                return send(otherSession, "POST", "/api/orders/101/" + second).statusCode();
            });
            if (!ready.await(5, TimeUnit.SECONDS)) throw new IllegalStateException("ready timeout");
            start.countDown();
            return List.of(a.get(15, TimeUnit.SECONDS), b.get(15, TimeUnit.SECONDS));
        }
    }
}

10. 偏离流程时怎样恢复

偏差恢复方式
Agent 跳过访谈直接编码先检查业务表是否都已决定；缺失的决定回到 grill-with-docs，已清楚的事实不用重复问。
to-spec 重新问了一整轮需求指向已确认的规格素材；只补真正缺失的决定。测试 seam 已确认时直接引用。
任务只写“实现 Service”要求以一个可通过 HTTP/界面验收的行为重新拆分。
测试 mock 了整个 Service恢复真实 HTTP + H2 seam，保留数据库夹具准备，但通过接口断言状态。
并发测试只顺序调用两个接口增加同步起跑的两个真实请求；同时检查结果组合、最终状态和版本。
出现 session/token 错误分别检查认证 Cookie 与 CSRF token；不要用关闭安全功能让测试通过。
审查说没有 diff核对基线、未提交改动和未跟踪文件。
上下文快满了先让任务、规格和关键决定落到持久产物；在阶段边界交接，下一会话读取明确路径。
