GitHub Pages branch 部署与项目结构

整理日期：2026-07-29
目标：不使用自定义部署 workflow，直接从 main 分支根目录发布；入口放在根目录，知识内容继续留在 public/。

核心结论

Learn-AI 使用 GitHub Pages 的 Deploy from a branch 模式，发布源固定为 main 和 / (root)。GitHub 的分支发布只允许分支根目录或 /docs，因此把原来 public/ 中的入口移动为根目录的 index.html，而学习页面、样式和脚本继续保留在 public/notes/ 与 public/assets/。GitHub Pages：配置发布来源

默认线上地址是 https://toik001.github.io/Learn-AI/。这是项目站点，仓库名会成为 URL 子路径；站内链接必须使用相对路径，不能写成以 / 开头的站点根路径。GitHub Pages：站点类型

项目结构

text
.
├── .nojekyll                    # 跳过 Jekyll 转换
├── index.html                   # Pages 根入口
├── AGENTS.md
├── README.md
├── public/
│   ├── manifest.json
│   ├── assets/
│   │   ├── style.css
│   │   └── app.js
│   └── notes/<category>/
│       └── YYYY-MM-DD-主题.html
└── scripts/
    ├── build-html-index.mjs
    ├── verify-site.mjs
    └── test-*.mjs

.nojekyll 让 GitHub Pages 原样发布现有 HTML，避免 Jekyll 把页面中的模板符号当作构建语法。由于发布源是仓库根目录，已提交的工程文件也属于公开仓库范围，任何密钥和私有资料都不得提交。

链接计算

根首页引用资源时使用 public/assets/style.css 和 public/assets/app.js，知识卡片链接以 public/notes/ 开头。知识页位于 public/notes/<category>/，返回根首页需要三级相对路径 ../../../index.html；知识页之间的分类导航仍按各自文件位置计算。

scripts/build-html-index.mjs 负责统一计算这些路径。新增、移动或删除页面后不要手工维护首页，直接重新运行生成器。

首次启用 GitHub Pages

  1. 打开仓库的 Settings → Pages。
  2. 在 Build and deployment → Source 选择 Deploy from a branch。
  3. Branch 选择 main，目录选择 / (root)，然后保存。
  4. 等待 GitHub 完成第一次构建，再访问项目站点。

Pages Source 是仓库级设置，不能仅通过 Git 提交完成。保存后，每次推送 main 都会触发 Pages 的内置分支发布。GitHub Pages：从分支发布

本地维护与验证

shell
node scripts/build-html-index.mjs
test -s index.html
test ! -e public/index.html
node --check scripts/build-html-index.mjs
node --check scripts/verify-site.mjs
node --check public/assets/app.js
for test_file in scripts/test-*.mjs; do node "$test_file"; done
node scripts/verify-site.mjs
node scripts/build-html-index.mjs
git diff --exit-code -- index.html public
git diff --check

分支发布没有自定义 workflow 门禁，所以本地校验是提交前的质量控制。完整性校验会检查根入口、本地资源、知识页链接、片段锚点、重复 ID、页面元数据和外链安全属性。

常见问题

现象常见原因处理方式
站点 404Source、分支或目录选择错误确认 Deploy from a branch、main、/ (root)
首页有样式但知识页 404根首页仍使用旧的 notes/ 路径运行索引生成器，确认链接以 public/notes/ 开头
知识页无法返回首页仍指向已删除的 public/index.html重新生成导航，目标应为 ../../../index.html
刚推送仍显示旧内容Pages 构建或缓存尚未刷新查看仓库 Pages 状态并稍后强制刷新

GitHub 的 404 排查重点包括发布源、入口文件名和访问地址。入口文件必须使用小写 index.html。GitHub Pages：404 排查
