Pi 安装配置与使用教程

最短路径：准备 Node.js 22.19.0 或更高版本 → 安装 @earendil-works/pi-coding-agent → 用 /login 或环境变量配置 Provider → 在一个无敏感信息的练习仓库启动 pi → 先做只读探索，再允许修改。

验证范围：本文命令和配置已与 2026-08-10 主分支文档/CLI 源码核对，但涉及 OAuth、付费模型和第三方云服务的流程未执行外部端到端验证。

快速阅读： 核心结论 · 安装 · 认证 · 工作流 · 会话 · 排错 · 资料

核心结论

  1. 新安装必须使用新 scope。当前包是 @earendil-works/pi-coding-agent；旧 @mariozechner/* 停在 0.73.1，升级可能需要运行两次 pi update。
  2. Project Trust 不是 Sandbox。它只决定项目本地设置、Package、Extension 和 Skill 是否加载；Pi 仍继承宿主进程的文件、网络、命令和凭据权限。
  3. 先选 Provider，再选模型。Provider 管理模型目录、认证与 wire protocol；/model 只展示当前可认证且工具能力可用的模型。
  4. Session 默认持久化并可分支。-c 继续最近会话，-r 浏览恢复，/tree 在同一 JSONL 内分支；敏感代码和工具输出因此会进入本地历史。
  5. 四种模式有不同信任行为。Interactive 可以询问信任；print、JSON 和 RPC 不会弹窗，未保存信任时会按全局 defaultProjectTrust 决定是否忽略项目资源。

环境与安装

前置条件

项目当前要求检查命令说明
Node.js>= 22.19.0node --version来自当前 coding-agent package.json 的 engines
npm/pnpm/bun任一可用npm --version官网给出三种全局安装方式
ShellmacOS/Linux 原生；Windows 需要可用 Bashbash --versionWindows 可使用 Git Bash、WSL、Cygwin/MSYS2 或自定义 shellPath
ProviderAPI Key 或受支持订阅登录启动后 /login实际费用和套餐规则由 Provider 决定
项目权限建议练习仓库、最小权限账号pwd、git status默认工具可读写文件并执行 Bash

推荐安装：npm

node --version
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
pi --version
pi --help

--ignore-scripts 禁用依赖 lifecycle scripts；官方说明正常 npm 安装不依赖 install scripts。若你的 Node.js 低于要求，应先用 nvm、mise、fnm 或系统包管理器升级，而不是强行忽略 engines。

其他安装方式

# 官方安装脚本：执行前建议先下载并审查内容
curl -fsSL https://pi.dev/install.sh -o /tmp/pi-install.sh
less /tmp/pi-install.sh
sh /tmp/pi-install.sh

# pnpm / bun
pnpm add -g --ignore-scripts @earendil-works/pi-coding-agent
bun add -g --ignore-scripts @earendil-works/pi-coding-agent

Windows 官网提供 PowerShell 安装脚本；如果 Bash 未被自动发现，可在 ~/.pi/agent/settings.json 设置 shellPath。生产环境应优先固定 release 与校验摘要，而不是每次从 main 构建。

从旧 scope 迁移

pi --version
pi update
# 若最初版本早于 0.73.1，第一次只会升到旧 scope 的最终版本；再执行一次
pi update
pi --version

官方公告说明 CLI 名仍是 pi，~/.pi/agent/ 下的配置和 Session 不改位置。旧包未下架，所以固定旧版本仍可复现，但不应作为新项目安装说明。

认证与模型

安装@earendil-works/pi-coding-agent
认证/login 或环境变量
目录内置 + 自动刷新 + models.json
选择/model 或 Ctrl+L
运行工具模型 + thinking level

Provider 是运行时单元，拥有模型目录、认证与 stream 行为；model 是该 Provider 下的具体能力和上下文窗口定义。

方式一：订阅/OAuth 登录

pi
/login
# 选择 ChatGPT Plus/Pro (Codex)、Claude Pro/Max、GitHub Copilot 等受支持项
/model
/session

Token 存储在 ~/.pi/agent/auth.json 并在支持时自动刷新。订阅是否允许第三方 Harness、是否额外计费以及组织策略会变化，必须阅读对应 Provider 当前条款。例如 Pi 文档特别提示 Claude Pro/Max 的第三方 Harness 使用可能走 extra usage，而非套餐限额。

方式二：API Key 环境变量

# 只选择一个实际使用的 Provider；不要把真实值提交到仓库
export ANTHROPIC_API_KEY="..."
# 或 OPENAI_API_KEY / GEMINI_API_KEY / OPENROUTER_API_KEY 等

pi --provider anthropic --model "claude-*"
pi --list-models "claude"

环境变量优于把明文 Key 写进项目文件。也可以通过 /login 把 API Key 存入 auth.json；该文件同样属于敏感凭据，需限制权限并纳入备份/清理策略。

模型选择与切换

操作用途注意
/model 或 Ctrl+L交互选择模型切换 Provider 后历史会被尽力转换，不保证推理块完全等价
Ctrl+P / Shift+Ctrl+P循环 scoped models先用 /scoped-models 或 enabledModels 限定集合
Shift+Tab调整 thinking level实际支持范围取决于模型
pi update --models强制刷新模型目录离线环境使用已有缓存
~/.pi/agent/models.json增加兼容 API 的 Provider/模型自定义 OAuth 或协议用 Extension 更合适

最小全局配置

{
  "defaultProvider": "anthropic",
  "defaultModel": "claude-sonnet-*",
  "defaultThinkingLevel": "medium",
  "defaultProjectTrust": "ask",
  "compaction": {
    "enabled": true,
    "reserveTokens": 16384,
    "keepRecentTokens": 20000
  },
  "retry": { "enabled": true, "maxRetries": 3 }
}

保存到 ~/.pi/agent/settings.json。模型 ID 会变化，通配或交互选择比复制过期示例更稳妥；若团队要求确定性，应固定已验证的模型 ID 和 Pi 版本。

项目上下文与信任

Pi 从全局、父目录到当前目录加载 AGENTS.md 或 CLAUDE.md；AGENTS.override.md 可替换同目录的普通文件。.pi/SYSTEM.md 替换系统提示，APPEND_SYSTEM.md 追加内容。

状态InteractivePrint/JSON/RPC项目资源
无保存决定，默认 ask发现项目资源时询问不弹窗，忽略项目资源上下文文件仍可加载；项目 Extension/设置不执行
--approve本次信任本次信任允许加载项目设置、资源和 Extension
--no-approve本次忽略本次忽略只使用全局/显式安全资源
/trust写入 trust.json，重启生效不适用交互命令最近的当前/父路径决定优先

安全重点：信任项目意味着项目 Extension 可执行代码、Package 可安装依赖；但“不信任”也不限制模型调用内置 Bash 对当前用户可访问的文件。需要真正隔离时使用容器、受限账号、网络策略或官方文档列出的 Gondolin/OpenShell 模式。

日常工作流

场景一：只读认识仓库

cd /path/to/practice-repo
git status --short
pi --tools read,grep,find,ls "阅读仓库，不修改文件。说明入口、测试命令和三个主要风险。"
# 完成后再次验证
git status --short

显式 allowlist 比只在提示中说“不要修改”更可靠。第一次使用新模型、新 Extension 或陌生仓库时都应先走只读流程。

场景二：受控局部修改

git switch -c experiment/pi-small-fix
pi "只修改指定模块；先说明计划，再补测试并运行相关测试。不要提交。"

git status --short
git diff --check
git diff

Pi 没有内置 plan mode，但可以把计划写进会话或文件。真正的完成证据仍来自 Git diff、测试、lint 和程序行为，而不是模型自述。

场景三：修复测试失败

pi "运行最小相关测试，解释根因，先新增或确认失败测试，再做最小修复。最后重跑。"
# Esc：取消当前模型/工具；输入新消息可 steer；Alt+Enter 可排队 follow-up

运行中按 Enter 发送 steering，会在当前工具执行后、下一次模型调用前送达；Alt+Enter 是 follow-up，只在 Agent 原本完成后继续。长任务可用这两个队列修正方向，而无需丢弃 session。

场景四：脚本与流水线

# 一次性文本输出，不保存 session，并忽略未信任项目资源
pi -p --no-session --no-approve --tools read,grep,find,ls \
  "总结当前项目的公开 API；不要修改文件。"

# JSONL 事件流，适合机器消费
pi --mode json --no-session --no-approve "检查测试失败原因"

非交互模式不会弹 trust prompt。CI 中应固定版本、模型、工具 allowlist、超时、工作目录、凭据权限和输出 schema；不要依赖用户主目录中不可见的全局 Extension。

场景五：减少启动网络请求

PI_OFFLINE=1 pi
# 或
pi --offline

Offline 会关闭版本检查、Package 更新检查和安装/更新 Telemetry 等启动网络操作，但模型 Provider 本身若是云 API 仍需要网络；这不是把云模型变成本地模型。

会话管理

命令行为适用场景
pi -c继续当前工作目录最近 session回到刚才中断的任务
pi -r交互选择历史 session同一仓库存在多个任务
/session查看路径、ID、消息、Token 和成本记录当前运行信息
/tree跳到历史 entry，在同一文件创建分支尝试另一种实现而保留旧路径
/fork从旧用户消息创建新 session 文件需要独立文件与后续生命周期
/clone复制当前 active branch 到新 session保留当前上下文后开始新分支
/compact摘要旧消息，保留最近上下文接近 context limit；摘要是有损的
/export//share导出 HTML/JSONL 或上传 gist分享前必须审查密钥、代码和日志
--no-session临时运行，不持久化CI、敏感一次性检查、可重复脚本

默认目录是 ~/.pi/agent/sessions/，可通过 --session-dir、PI_CODING_AGENT_SESSION_DIR 或 settings 的 sessionDir 改变，优先级依次递减。

推荐的会话卫生

  • 一个明确任务一个命名 session；用 --name 或 /name 标识。
  • 切换完全不同的目标时用新 session，不要无限依赖 Compaction。
  • 把关键决策、测试命令和当前阻塞写入仓库可审查文件，Session 不是唯一事实源。
  • 定期清理含敏感数据的导出、gist 和本地历史；不要把 auth.json 放入项目。

常见问题

现象优先检查处理
安装时报 engines/语法错误node --version升级到 Node.js 22.19.0+，重新全局安装
pi 仍是旧包which pi、pi --version、全局包列表运行两次 pi update 或卸载旧 scope 后安装新包
找不到模型Provider 凭据、pi --list-models、目录缓存重新 /login，运行 pi update --models，核对模型是否支持工具调用
项目 Extension 未加载Project Trust、.pi/settings.json、启动头诊断审查后 /trust 并重启，或仅本次 --approve
CI 与本地行为不同非交互 trust、全局资源、模型和 Pi 版本固定版本并显式传 --approve/--no-approve、工具、模型和资源参数
长会话遗忘细节/session、Compaction 配置、session tree查看完整 JSONL/树，重新注入事实，或新建目标明确的 session
命令权限过大启动用户、容器 mount、网络和凭据停止运行；用最小权限容器/账号重新启动，不依赖提示词
TUI 颜色/按键异常终端类型、tmux、Windows 键位、主题查 terminal-setup/keybindings/windows 文档，必要时设置 shellPath

30 分钟验收练习

  1. 在无敏感信息的练习仓库安装并启动 Pi，记录版本和选定 Provider/model。
  2. 用只读工具 allowlist 让 Pi 解释项目，确认 git status 无变化。
  3. 建立新分支，允许 edit/write/bash，完成一个小修改并用测试验证。
  4. 用 /tree 回到修改前提示，尝试另一方案；确认两个分支仍在同一 session。
  5. 退出后用 pi -c 恢复，再用 /session 检查路径、Token 和成本。
  6. 最后检查本地 session 是否包含敏感文本，并制定清理规则。
