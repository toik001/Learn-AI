#核心结论

  • 工具调用是一项应用能力，不是模型获得了系统权限。模型只能返回工具名和参数；应用解析、授权、执行并决定向模型回传什么。Spring 官方同样强调模型不会接触工具 API，真正执行者是客户端应用。Spring AI Tool Calling
  • JSON Schema 只约束数据形状。它可以描述类型、必填项和取值范围，却不证明模型输出真实、不证明当前用户有权限，也不覆盖租户归属、审批、幂等和预算等业务不变量。
  • Spring AI 2.0.0 有三种执行控制模式。ChatClient 的 framework-controlled 模式适合已在工具 handler 内完成强制策略的低风险调用；显式 ToolCallingAdvisor 的 Advisor-controlled 模式适合扩展可观测性、记忆与循环判定；需要在每轮插入独立审批、预算和条件分支时选择 user-controlled，并由应用使用 ToolCallingManager 驱动生命周期。
  • 授权、审批和预算始终由应用掌控。无论谁驱动循环，allowlist、Bean Validation、主体与租户校验、超时、错误脱敏、审计及执行预算都不是模型或 JSON Schema 能替代的。

#结构化决策模型

一次模型响应至少可能落入三种语义。不要只根据字符串外观猜测它属于哪一种：

响应形态含义应用处理能否直接产生副作用
普通文本答复自然语言解释或追问，没有机器可执行承诺内容安全检查后展示；事实仍需证据不能
最终结构化答复映射为 FinalAnswer 等 DTO，便于下游稳定消费Schema、Bean Validation 与业务不变量检查后消费不能；DTO 合法不等于动作获批
结构化工具请求模型选择工具名并给出 JSON 参数解析为 ToolCall，经过 allowlist、授权、校验、审批与预算后才执行只有应用放行后才可能

Spring AI 的 StructuredOutputConverter 围绕文本补全做“尽力而为”的转换，官方明确说明模型并不保证遵守格式；需要额外校验。它也不用于 Tool Calling，因为工具协议本身已经携带结构化参数。StructuredOutputValidationAdvisor 可以依据 JSON Schema 校验结构并有限重试，但重试成功仍只代表结构有效。Structured Output Converter、Recursive Advisors

JSON Schema 2020-12 规范分为 Core 与 Validation。它擅长表达“对象必须有 ticketId 且为字符串”，但下面五件事必须由应用另行判断：

  1. 真实性：ticketId 是否存在、状态是否最新。
  2. 权限：当前主体能否查看该对象。
  3. 租户边界：该工单是否属于受信上下文中的 tenant，而不是模型参数声称的 tenant。
  4. 安全与业务不变量：动作是否可逆、是否已审批、是否幂等。
  5. 资源约束：本轮是否还有步数、时间、调用次数与成本预算。

#Tool Calling 调用过程

1. 用户请求
2. 工具定义
3. 模型决策
4. 结构化工具调用
5. 应用授权
6. 校验后执行
7. 安全 Observation
8. 模型 / 最终响应
横切护栏：可信身份与租户 · 工具 allowlist · Bean Validation · 对象级授权 · 独立审批 · 步数/时间/成本预算 · 超时 · 错误脱敏 · 审计

等价文字说明：应用收到用户请求后，只向模型提供当前主体可用的工具定义；模型选择直接答复或生成结构化工具调用。应用把调用视为不可信输入，先核对工具 allowlist、可信身份与租户、参数和对象级权限，再检查审批及剩余预算；仅通过后才在超时和最小权限凭证下执行。工具结果会被裁剪、脱敏并封装成安全 Observation，随后交给模型生成答复或由应用直接返回。身份、授权、预算、错误和审计护栏横切全部八个节点。

这个流程的关键分界线在第 5 节点：模型可以建议使用哪个工具，只有应用可以授权调用。把工具定义发给模型是可用性提示，不是权限授予。

#三种执行控制模式

Spring AI 2.0.0 官方文档把工具执行生命周期分成三类。此前由 ChatModel 实现内部自动执行的方式从 2.0.0 起已弃用，计划在 3.0.0 移除；新代码应使用 ChatClient + ToolCallingAdvisor，或显式采用用户控制循环。

模式循环由谁驱动Spring AI 2.0.0 行为应用责任选择建议
Framework-controlled（框架控制） ChatClient 自动注册的 ToolCallingAdvisor Advisor 拦截工具请求，经 ToolCallingManager 执行并回传，直到模型给出最终响应 在每个 handler 内强制执行身份、租户、参数、对象授权、超时、预算和错误边界；按请求收窄工具集合 只读、低风险、循环无需定制，且所有强制策略都能封装在 handler / 自定义 manager 中时优先
Advisor-controlled（Advisor 控制） 应用显式配置的 ToolCallingAdvisor 仍由 Advisor 循环，可注入自定义 ToolCallingManager、循环资格检查、顺序与可观测 Advisor 自定义扩展不能取代业务授权；handler 和 manager 继续强制策略 需要观察每轮、结合记忆、定制循环资格或执行 manager，但不需要应用逐轮暂停时使用
User-controlled（用户控制） 业务 Agent Runtime 关闭自动 ToolCallingAdvisor；应用检查 ChatResponse，再使用 ToolCallingManager 执行 逐轮授权、审批、预算预占、进度推送、停止条件、安全 Observation 与审计 写操作、高风险动作、条件审批、强预算、人工介入或自定义分支所需的首选

边界提醒：“framework-controlled”只表示 Spring AI 驱动调用循环，不表示 Spring AI 替你理解 RBAC、租户、审批单或成本上限；“user-controlled”中的 user 指使用框架的应用开发者控制生命周期，不是让终端用户直接执行任意工具。

#Java 21 类型设计

Java 21 的 sealed interface 让模型决策成为封闭代数类型：调用方必须处理最终答复或工具请求，不能把任意文本偷偷混进可执行分支。record 隐式为 final，可以作为 sealed interface 的许可实现。下面示例依赖 Jakarta Bean Validation API；所有集合在构造时复制。

import jakarta.validation.ConstraintViolation;
import jakarta.validation.Valid;
import jakarta.validation.Validator;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Pattern;
import jakarta.validation.constraints.Size;

import java.time.Duration;
import java.util.List;
import java.util.Objects;
import java.util.Set;

sealed interface ModelDecision permits FinalAnswer, ToolRequest {}

record FinalAnswer(@NotBlank @Size(max = 2_000) String text)
        implements ModelDecision {
    public FinalAnswer {
        text = Required.text(text, "text");
    }
}

record ToolRequest(ToolCall call) implements ModelDecision {
    public ToolRequest {
        Objects.requireNonNull(call, "call");
    }
}

sealed interface ToolArguments permits ServiceStatusQuery, TicketQuery {}

record ToolCall(String name, ToolArguments arguments) {
    public ToolCall {
        name = Required.text(name, "name");
        Objects.requireNonNull(arguments, "arguments");
    }
}

record ServiceStatusQuery(
        @NotBlank
        @Pattern(regexp = "[A-Z][A-Z0-9_-]{1,31}")
        String serviceCode) implements ToolArguments {
    public ServiceStatusQuery {
        serviceCode = Required.text(serviceCode, "serviceCode");
    }
}

record TicketQuery(
        @NotBlank
        @Pattern(regexp = "TKT-[0-9]{6,12}")
        String ticketId) implements ToolArguments {
    public TicketQuery {
        ticketId = Required.text(ticketId, "ticketId");
    }
}

record UserContext(String userId, String tenantId, Set<String> permissions) {
    public UserContext {
        userId = Required.text(userId, "userId");
        tenantId = Required.text(tenantId, "tenantId");
        permissions = Set.copyOf(Objects.requireNonNull(permissions, "permissions"));
    }
}

enum AuthorizationCode {
    ALLOWED, UNKNOWN_TOOL, PERMISSION_DENIED, TENANT_MISMATCH,
    APPROVAL_REQUIRED, BUDGET_EXHAUSTED
}

record AuthorizationDecision(AuthorizationCode code, String reason) {
    public AuthorizationDecision {
        Objects.requireNonNull(code, "code");
        reason = Required.text(reason, "reason");
    }

    boolean allowed() {
        return code == AuthorizationCode.ALLOWED;
    }
}

interface ToolPolicy {
    AuthorizationDecision authorize(UserContext user, ToolCall call);
}

final class AllowlistToolPolicy implements ToolPolicy {
    private static final Set<String> READ_TOOLS =
            Set.of("readServiceStatus", "readTenantTicket");

    @Override
    public AuthorizationDecision authorize(UserContext user, ToolCall call) {
        if (!READ_TOOLS.contains(call.name())) {
            return new AuthorizationDecision(
                    AuthorizationCode.UNKNOWN_TOOL, "Tool is not allowlisted");
        }
        if (!user.permissions().contains("service-desk:read")) {
            return new AuthorizationDecision(
                    AuthorizationCode.PERMISSION_DENIED, "Read permission is required");
        }
        return new AuthorizationDecision(AuthorizationCode.ALLOWED, "Allowed");
    }
}

enum PublicToolError {
    INVALID_REQUEST("Tool request is invalid", false),
    FORBIDDEN("Tool request is not permitted", false),
    NOT_FOUND("Requested resource was not found", false),
    TEMPORARILY_UNAVAILABLE("Tool is temporarily unavailable", true),
    TIMEOUT("Tool execution timed out", true),
    LIMIT_EXCEEDED("Execution limit reached; human handoff required", false);

    private final String publicMessage;
    private final boolean retryable;

    PublicToolError(String publicMessage, boolean retryable) {
        this.publicMessage = publicMessage;
        this.retryable = retryable;
    }

    String publicMessage() {
        return publicMessage;
    }

    boolean retryable() {
        return retryable;
    }
}

record SafeToolFailure(PublicToolError code, String correlationId) {
    public SafeToolFailure {
        Objects.requireNonNull(code, "code");
        correlationId = Required.text(correlationId, "correlationId");
    }
}

// 只写私有日志/Trace，不返回给模型或终端用户。
record PrivateDiagnostic(
        String correlationId,
        String toolName,
        String tenantId,
        String exceptionType,
        String redactedDetail) {
    public PrivateDiagnostic {
        correlationId = Required.text(correlationId, "correlationId");
        toolName = Required.text(toolName, "toolName");
        tenantId = Required.text(tenantId, "tenantId");
        exceptionType = Required.text(exceptionType, "exceptionType");
        redactedDetail = Required.text(redactedDetail, "redactedDetail");
    }
}

final class ToolBoundary {
    private final Validator validator;
    private final ToolPolicy policy;
    private final Duration timeout = Duration.ofSeconds(2);

    ToolBoundary(Validator validator, ToolPolicy policy) {
        this.validator = Objects.requireNonNull(validator);
        this.policy = Objects.requireNonNull(policy);
    }

    void authorizeAndValidate(
            UserContext user, ToolCall call, @Valid Object typedArguments) {
        AuthorizationDecision decision = policy.authorize(user, call);
        if (!decision.allowed()) {
            throw new PolicyRejectedException(decision.code());
        }
        Set<ConstraintViolation<Object>> violations =
                validator.validate(typedArguments);
        if (!violations.isEmpty()) {
            throw new InvalidToolArgumentsException();
        }
        // 调用下游时应用 timeout，并使用 user.tenantId() 构造查询范围；
        // 永远不要信任模型参数中的 tenant、URL、SQL 或命令。
    }
}

final class Required {
    private Required() {}

    static String text(String value, String name) {
        Objects.requireNonNull(value, name);
        if (value.isBlank()) {
            throw new IllegalArgumentException(name + " must not be blank");
        }
        return value;
    }
}

final class PolicyRejectedException extends RuntimeException {
    PolicyRejectedException(AuthorizationCode code) {
        super(code.name());
    }
}

final class InvalidToolArgumentsException extends RuntimeException {}

ToolCall.arguments 使用封闭的类型化 record，而不是嵌套可变的 Map<String, Object>：仅对 Map 调用 Map.copyOf 只能冻结外层，内部 List、Map 或对象仍可能被修改。协议 adapter 应先按 allowlist 选择目标类型，再把 JSON 解码为对应 record 并执行 Bean Validation。

上例中的 timeout 是执行约束，不是装饰信息：实际 adapter 必须把它交给 HTTP / 数据库客户端并在到期后取消。安全错误只暴露稳定枚举、通用消息和关联 ID；异常类型、下游地址、堆栈、SQL、token 与原始响应仅进入访问受控且已脱敏的私有诊断。

只读工具与显式 Advisor-controlled 示例

下面的主示例显式配置 ToolCallingAdvisor，把安全异常处理器和受护栏保护的 ToolCallingManager 真正接入调用链。framework-controlled 的自动 Advisor 仍是简单只读场景的默认选择；一旦承诺 run 级预算、最大步数或重复调用边界，就必须由实际 handler / manager 强制执行，不能只写在说明文字里。

ToolContext 数据不会发送给模型，但“不发送给模型”不等于“可信”。可信身份必须先从 Spring Security Authentication 与服务端 session 派生，再由应用写入 context；handler 读取时还要验证类型、tenant 和当前活动 run 一致。客户端请求体、模型参数或任意调用方自己构造的 Map 都不能成为身份来源。

// 该对象由服务端 session adapter 创建，不从请求 JSON 反序列化。
record ServerAgentSession(String sessionId, String tenantId) {}

record ServiceDeskPrincipal(
        String userId, Set<String> tenantIds, Set<String> permissions) {}

final class UserContextFactory {
    UserContext from(
            Authentication authentication, ServerAgentSession serverSession) {
        if (authentication == null || !authentication.isAuthenticated()
                || !(authentication.getPrincipal()
                        instanceof ServiceDeskPrincipal principal)) {
            throw new PolicyRejectedException(AuthorizationCode.PERMISSION_DENIED);
        }
        if (!principal.tenantIds().contains(serverSession.tenantId())) {
            throw new PolicyRejectedException(AuthorizationCode.TENANT_MISMATCH);
        }
        return new UserContext(
                principal.userId(),
                serverSession.tenantId(),
                principal.permissions());
    }
}

record TrustedToolContext(String userId, String tenantId, Duration timeout) {
    static TrustedToolContext from(
            ToolContext context, RunContextAccessor runs) {
        Object rawUser = context.getContext().get("trustedUserContext");
        Object rawTimeout = context.getContext().get("trustedTimeout");
        if (!(rawUser instanceof UserContext candidate)
                || !(rawTimeout instanceof Duration timeout)
                || timeout.isZero()
                || timeout.isNegative()
                || timeout.compareTo(Duration.ofSeconds(2)) > 0) {
            throw new PolicyRejectedException(AuthorizationCode.PERMISSION_DENIED);
        }

        UserContext active = runs.requireCurrent().user();
        if (!active.userId().equals(candidate.userId())
                || !active.tenantId().equals(candidate.tenantId())) {
            throw new PolicyRejectedException(AuthorizationCode.TENANT_MISMATCH);
        }
        return new TrustedToolContext(
                active.userId(), active.tenantId(), timeout);
    }
}

@Component
final class ServiceDeskReadTools {
    private final ServiceStatusRepository statusRepository;
    private final TicketRepository ticketRepository;
    private final Validator validator;
    private final ServiceDeskAuthorization authorization;
    private final RunContextAccessor runs;

    ServiceDeskReadTools(
            ServiceStatusRepository statusRepository,
            TicketRepository ticketRepository,
            Validator validator,
            ServiceDeskAuthorization authorization,
            RunContextAccessor runs) {
        this.statusRepository = statusRepository;
        this.ticketRepository = ticketRepository;
        this.validator = validator;
        this.authorization = authorization;
        this.runs = runs;
    }

    @Tool(
        name = "readServiceStatus",
        description = "Read the current status of one allowlisted service code")
    ServiceStatusView readServiceStatus(
            ServiceStatusQuery query, ToolContext context) {
        TrustedToolContext trusted = TrustedToolContext.from(context, runs);
        ToolGuards.validate(validator, query);
        authorization.requireServiceRead(trusted, query.serviceCode());
        return statusRepository.findAllowlisted(
                trusted.tenantId(), query.serviceCode(), trusted.timeout());
    }

    @Tool(
        name = "readTenantTicket",
        description = "Read one ticket visible to the authenticated tenant")
    TicketView readTenantTicket(TicketQuery query, ToolContext context) {
        TrustedToolContext trusted = TrustedToolContext.from(context, runs);
        ToolGuards.validate(validator, query);
        authorization.requireTicketRead(
                trusted.userId(), trusted.tenantId(), query.ticketId());
        return ticketRepository.findTenantScoped(
                trusted.tenantId(), query.ticketId(), trusted.timeout());
    }
}

final class ExecutionBudget {
    private final int maxSteps;
    private final Instant deadline;
    private int reservedSteps;

    private ExecutionBudget(int maxSteps, Duration maxDuration) {
        this.maxSteps = maxSteps;
        this.deadline = Instant.now().plus(maxDuration);
    }

    static ExecutionBudget start(int maxSteps, Duration maxDuration) {
        if (maxSteps < 1 || maxDuration.isZero() || maxDuration.isNegative()) {
            throw new IllegalArgumentException("Budget must be positive");
        }
        return new ExecutionBudget(maxSteps, maxDuration);
    }

    synchronized void reserve(int requestedCalls) {
        if (requestedCalls < 1
                || reservedSteps + requestedCalls > maxSteps
                || Instant.now().isAfter(deadline)) {
            throw new RunLimitException(PublicToolError.LIMIT_EXCEEDED);
        }
        reservedSteps += requestedCalls; // 原子预占，发生在 delegate 执行之前
    }
}

final class DuplicateToolCallGuard {
    private final Set<ToolCall> seen = new HashSet<>();

    synchronized void requireFirstOccurrence(List<ToolCall> calls) {
        Set<ToolCall> batch = new HashSet<>(calls);
        if (batch.size() != calls.size()
                || !Collections.disjoint(batch, seen)) {
            throw new RunLimitException(PublicToolError.LIMIT_EXCEEDED);
        }
        seen.addAll(batch); // synchronized 内：校验通过后原子写入历史集合
    }
}

record RunContext(
        UserContext user,
        ExecutionBudget budget,
        DuplicateToolCallGuard duplicateCalls) {}

interface RunContextAccessor {
    RunContext requireCurrent();
    <T> T withRun(RunContext run, Supplier<T> action);
}

final class RunLimitException extends RuntimeException {
    private final PublicToolError code;

    RunLimitException(PublicToolError code) {
        super(code.name());
        this.code = code;
    }

    PublicToolError code() {
        return code;
    }
}

// 应用 adapter：先按 allowlist 选择类型，再解码成 ToolArguments record 并校验。
interface ModelToolCallAdapter {
    List<ToolCall> decodeAndValidate(ChatResponse response);
}

final class GuardedToolCallingManager implements ToolCallingManager {
    private final ToolCallingManager delegate;
    private final RunContextAccessor runs;
    private final ModelToolCallAdapter adapter;
    private final ToolPolicy policy;
    private final AuditSink audit;

    GuardedToolCallingManager(
            ToolCallingManager delegate,
            RunContextAccessor runs,
            ModelToolCallAdapter adapter,
            ToolPolicy policy,
            AuditSink audit) {
        this.delegate = delegate;
        this.runs = runs;
        this.adapter = adapter;
        this.policy = policy;
        this.audit = audit;
    }

    @Override
    public List<ToolDefinition> resolveToolDefinitions(
            ToolCallingChatOptions options) {
        return delegate.resolveToolDefinitions(options);
    }

    @Override
    public ToolExecutionResult executeToolCalls(
            org.springframework.ai.chat.prompt.Prompt prompt,
            ChatResponse response) {
        RunContext run = runs.requireCurrent();
        List<ToolCall> calls = adapter.decodeAndValidate(response);

        for (ToolCall call : calls) {
            AuthorizationDecision decision = policy.authorize(run.user(), call);
            if (!decision.allowed()) {
                throw new PolicyRejectedException(decision.code());
            }
        }
        run.duplicateCalls().requireFirstOccurrence(calls);
        run.budget().reserve(calls.size());
        audit.recordAuthorized(run.user(), calls);
        return delegate.executeToolCalls(prompt, response);
    }
}

final class SafeToolExecutionExceptionProcessor
        implements ToolExecutionExceptionProcessor {
    private final RunContextAccessor runs;
    private final PublicErrorClassifier classifier;
    private final PrivateDiagnosticSink diagnostics;
    private final SafeJson safeJson;

    SafeToolExecutionExceptionProcessor(
            RunContextAccessor runs,
            PublicErrorClassifier classifier,
            PrivateDiagnosticSink diagnostics,
            SafeJson safeJson) {
        this.runs = runs;
        this.classifier = classifier;
        this.diagnostics = diagnostics;
        this.safeJson = safeJson;
    }

    @Override
    public String process(ToolExecutionException exception) {
        RunContext run = runs.requireCurrent();
        String correlationId = UUID.randomUUID().toString();
        PublicToolError code = classifier.classify(exception.getCause());

        PrivateDiagnostic diagnostic = new PrivateDiagnostic(
                correlationId,
                exception.getToolDefinition().name(),
                run.user().tenantId(),
                exception.getCause().getClass().getSimpleName(),
                "Full cause retained only in restricted diagnostics");
        diagnostics.record(diagnostic, exception);

        // 固定 schema 只含枚举 code 与 correlationId；绝不使用 exception.getMessage()。
        return safeJson.write(new SafeToolFailure(code, correlationId));
    }
}

@Component
final class ServiceDeskAssistant {
    private final ChatClient chatClient;
    private final UserContextFactory users;
    private final RunContextAccessor runs;
    private final SafeFailureFactory safeFailures;

    ServiceDeskAssistant(
            ChatModel chatModel,
            ServiceDeskReadTools tools,
            UserContextFactory users,
            RunContextAccessor runs,
            ModelToolCallAdapter adapter,
            ToolPolicy policy,
            AuditSink audit,
            SafeToolExecutionExceptionProcessor safeProcessor,
            SafeFailureFactory safeFailures) {
        ToolCallingManager springManager = DefaultToolCallingManager.builder()
                .toolExecutionExceptionProcessor(safeProcessor)
                .build();
        ToolCallingManager guardedManager = new GuardedToolCallingManager(
                springManager, runs, adapter, policy, audit);
        ToolCallingAdvisor toolAdvisor = ToolCallingAdvisor.builder()
                .toolCallingManager(guardedManager)
                .build();
        this.chatClient = ChatClient.builder(chatModel)
                .defaultTools(tools)
                .defaultAdvisors(toolAdvisor)
                .build();
        this.users = users;
        this.runs = runs;
        this.safeFailures = safeFailures;
    }

    String answer(
            Authentication authentication,
            ServerAgentSession serverSession,
            String question) {
        UserContext user = users.from(authentication, serverSession);
        RunContext run = new RunContext(
                user,
                ExecutionBudget.start(4, Duration.ofSeconds(8)),
                new DuplicateToolCallGuard());

        return runs.withRun(run, () -> {
            try {
                return chatClient.prompt()
                        .user(question)
                        .toolContext(Map.of(
                                "trustedUserContext", user,
                                "trustedTimeout", Duration.ofSeconds(2)))
                        .call()
                        .content();
            }
            catch (RunLimitException limit) {
                // 固定 LIMIT_EXCEEDED + correlationId，并把 run 放入人工接管队列。
                return safeFailures.limitExceededAndHandoff(run, limit);
            }
            catch (PolicyRejectedException | InvalidToolArgumentsException rejected) {
                // manager 自身的执行前拒绝不会进入 Spring 的 exception processor；
                // 因此由同一安全工厂映射，禁止返回 rejected.getMessage()。
                return safeFailures.rejected(run, rejected);
            }
        });
    }
}

ChatClient.builder(chatModel).defaultTools(tools) 与显式 ToolCallingAdvisor 都是 Spring AI 2.0.0 记录的 API。此处 GuardedToolCallingManager 在委托 Spring 执行前完成类型化解码、授权、重复调用检查和原子预算预占；每个 handler 仍再次执行可信 context、Bean Validation、对象级授权和下游超时。默认工具会对同一 builder 构建的 client 请求可见，因此生产代码还应按用例拆分 client，或使用每次请求的 .tools(...) 收窄暴露面。

不能依赖默认异常文本是安全的。Spring AI 2.0.0 官方说明，默认 DefaultToolExecutionExceptionProcessor 在默认配置下会把 RuntimeException 的 message 发回模型。示例明确把 SafeToolExecutionExceptionProcessor 注入 DefaultToolCallingManager：分类器只产生固定 PublicToolError，模型只收到 code 与 correlation ID；原始异常、工具名、tenant 和受限诊断留在应用侧。guarded manager 在 Spring delegate 之前产生的策略、参数或预算拒绝不会经过该 processor，所以 ServiceDeskAssistant 还用同一个安全工厂做外层映射。另一种可接受策略是配置 spring.ai.tools.throw-exception-on-error=true，并在最外层统一做同样的安全映射。

可信边界来自服务器。ServerAgentSession 必须由服务端 session adapter 创建，Authentication 必须由 Spring Security 提供。TrustedToolContext.from 不仅做类型转换，还把 context 中的 UserContext 与当前 run 交叉校验；因此即便内部调用方伪造 Map，也无法跨 user 或 tenant 执行。

若场景确实只需 framework-controlled 的自动循环，也要先替换自动配置使用的异常处理器；下面的 Bean 使 Spring 的默认 manager 使用同一个安全映射，而不是回传 RuntimeException message：

@Bean
ToolExecutionExceptionProcessor toolExecutionExceptionProcessor(
        SafeToolExecutionExceptionProcessor safeProcessor) {
    return safeProcessor;
}

@Bean
ChatClient frameworkControlledClient(
        ChatModel chatModel, ServiceDeskReadTools tools) {
    return ChatClient.builder(chatModel)
            .defaultTools(tools)
            .build(); // 自动 ToolCallingAdvisor；handler 仍强制全部业务策略
}

User-controlled 生命周期：插入审批与预算

需要人工批准或严格预算时，关闭本次调用的自动 Advisor。下面是刻意简化的生命周期伪代码；其中 extractDomainCalls 与 appendSafeRejections 是应用 adapter，不是 Spring AI API。只有当本轮全部请求通过 allowlist、类型化参数、对象授权、审批与预算预占后，才交给 ToolCallingManager 执行。

ToolCallback[] callbacks = ToolCallbacks.from(readOnlyTools);
ToolCallingManager toolCallingManager = DefaultToolCallingManager.builder()
        .toolExecutionExceptionProcessor(safeProcessor)
        .build();
ChatOptions options = ToolCallingChatOptions.builder()
        .toolCallbacks(callbacks)
        .build();

Prompt prompt = new Prompt(List.of(new UserMessage(question)), options);
ChatResponse response = chatModel.call(prompt);

for (int step = 0; response.hasToolCalls(); step++) {
    executionBudget.requireStepAvailable(step);       // 应用拥有

    List<ToolCall> requested = extractDomainCalls(response);
    for (ToolCall call : requested) {
        allowlist.requireKnown(call.name());          // 应用拥有
        Object typed = arguments.decodeAndValidate(call);
        toolPolicy.requireAuthorized(user, call);     // 应用拥有
        approval.requireIfRisky(user, call, typed);   // 应用拥有
        executionBudget.reserve(call);                // 应用拥有
        audit.recordApproved(user, call);
    }

    ToolExecutionResult result =
            toolCallingManager.executeToolCalls(prompt, response);
    prompt = new Prompt(
            sanitizeObservations(result.conversationHistory()), options);
    response = chatModel.call(prompt);
}

return safeFinalResponse(response);

若任一调用被拒绝，应用不能先执行其余调用再补记失败；应把拒绝转为无敏感信息的 Observation 或终止并转人工。预算预占要发生在执行前，成功或失败后按策略结算。重复工具调用必须用 run 内指纹或幂等键识别，并受最大步数、总耗时与成本三重上限约束。

若只需观察或定制框架循环，可显式构造 Advisor-controlled 配置，而不必接管全部循环：

var toolCallingAdvisor = ToolCallingAdvisor.builder()
        .toolCallingManager(policyEnforcingToolCallingManager)
        .toolExecutionEligibilityChecker(response ->
                response.hasToolCalls() && runBudget.hasRemainingSteps())
        .build();

var advisorControlledClient = ChatClient.builder(chatModel)
        .defaultAdvisors(toolCallingAdvisor)
        .build();

这段 Lambda 中的预算判定只决定是否继续循环；真正执行前的主体、对象、参数与审批校验仍应在 policyEnforcingToolCallingManager 或工具 handler 内强制完成。

returnDirect 的边界

默认情况下，工具结果会回给模型，由模型生成最终答复。设置 @Tool(returnDirect = true) 后，ToolCallingAdvisor 会在工具执行完成时退出循环，把结果直接交给 client，减少一次模型调用并避免模型改写。

return direct 不是 authorization direct。它跳过的是工具执行后的最终模型处理，不会也不应跳过执行前的 allowlist、身份与租户、参数、对象级授权、审批、预算和超时；也不会跳过执行后的输出字段过滤、脱敏、内容类型、响应大小和审计。若多个工具同时被请求，官方文档说明必须全部设置 returnDirect=true 才会直接返回。对内部实体或含敏感字段的结果，默认不要启用。

#练习与验收

练习

  1. 为 ServiceStatusQuery 写 JSON Schema，并列出 Schema 通过后仍需执行的五项业务检查。
  2. 实现 AllowlistToolPolicy 的参数化测试，覆盖未知工具、权限缺失和只读工具放行；证明测试不调用真实下游。
  3. 用 Bean Validation 测试空 ticketId、错误格式和超长值，再验证公开错误中不包含原始异常类名。
  4. 画出创建工单审批的 user-controlled 时序：必须标出工具未注册、草稿摘要绑定、审批过期、预算预占、幂等键和再次鉴权。
  5. 比较 framework-controlled 与 user-controlled 的代码和运行轨迹，说明为何高风险写操作选择后者。

本课验收标准

  • 能用一句话说明：模型提出 ToolCall，应用 ToolPolicy 才决定能否执行。
  • 能分别解释普通文本、FinalAnswer 与 ToolRequest，并说明 JSON Schema 不覆盖权限与真实性。
  • Java 21 契约包含 sealed ModelDecision、类型化不可变 ToolArguments record、allowlist、Bean Validation、可信租户上下文和公开/私有错误分离。
  • 能准确描述 framework-controlled、Advisor-controlled、user-controlled 三种模式，以及 Spring AI 2.0.0 中 ToolCallingAdvisor 与 ToolCallingManager 的分工。
  • 能证明实际调用链在 delegate 执行前完成审批、批次内/跨轮重复检查和预算预占；同一批次重复或第 5 次调用产生 LIMIT_EXCEEDED 并转人工，returnDirect 也不绕过授权和输出控制。
  • 能证明 framework-controlled 与 Advisor-controlled 都不依赖默认 RuntimeException message：模型只收到固定 PublicToolError 和 correlation ID。
  • 服务台只注册读取服务状态与租户工单两个工具；创建工单在批准前不可被模型调用。
  • 未知工具、畸形 JSON、Bean Validation、租户不匹配、超时、工具 5xx、重复调用、预算耗尽与安全公开错误均有自动化测试设计。
