#Agent 状态、上下文与记忆

Chat Memory 解决“这次给模型看哪些对话消息”，业务状态解决“任务现在执行到哪里”。二者不能共用一个模糊的 history 字段，更不能互相替代。

本文使用 Java 21、Spring AI 2.0.0 与 Spring Boot 4.0.x / 4.1.x，并保持模型供应商中立。整理日期与官方资料检索日期：2026-07-27。

#核心结论

  • AgentState 是业务事实，Prompt Context 是一次模型调用的投影。检查点、审批结果、工具执行状态、预算和版本必须独立持久化；不能寄希望于模型从聊天消息中“记住”。
  • Spring AI Chat Memory 不等于完整 Chat History。ChatMemoryRepository 负责消息存取，ChatMemory 决定保留与淘汰；完整对话、工具轨迹、业务审计应使用 Spring Data / 数据库等独立存储。Spring AI 2.0.0 Chat Memory
  • 会话标识必须显式、可信且隔离。所有 Memory Advisor 调用都要传 ChatMemory.CONVERSATION_ID；省略没有默认值，会在运行时抛出 IllegalArgumentException。conversationId 应由应用依据已认证 tenant / user 映射，而不是直接信任模型或请求正文。
  • 工具中间消息不是恢复账本。Spring AI 当前实现不会自动把工具调用期间与模型交换的中间消息存入 Chat Memory；部分持久化 Repository 还会过滤工具调用消息。每个决策、调用、Observation 和结果必须写入业务事件日志。Chat Memory — Memory in Chat Client
  • 记忆内容与 Observation 都是不可信且可能敏感的输入。原文先经过独立 DLP / 数据分类服务；Prompt 代码只接收结构化安全摘要，私有 payload 没有进入 Prompt DTO 的字段。私有诊断加密存储并与公开错误分开。OWASP 同样建议对敏感数据实施清洗、最小权限和严格访问控制。OWASP LLM02:2025

#四类信息不要混在一起

1. Run State

步骤、审批、预算、工具状态、版本；每一步持久化，可恢复。

2. Prompt Context

本次调用所需的脱敏、相关、未过期投影；调用后可丢弃。

3. Chat Memory

给模型维持连贯性的有限消息窗口；不是完整历史或审计账本。

4. Business Memory / History

工单事实、完整对话、事件和审计；按法规、租户与业务策略治理。

等价文字说明：运行状态记录任务当前可恢复位置；Prompt Context 从可信状态与候选资料中选择最少、相关、脱敏且未过期的信息；Chat Memory 只为模型保留有限对话上下文；长期业务记忆与完整历史由数据库持久化并接受访问控制、保留和删除策略。四层可以互相投影，但不能用同一份无边界消息列表代替。

层典型内容写入者 / 真相源生命周期绝不能承担
运行状态（Run State） tenantId、userId、runId、步骤、审批 ID、工具状态、知识版本、预算、version 业务 Agent Runtime；事务数据库是真相源 一次 run，可有合规保留期 不能让模型消息反推真实审批或执行结果
提示上下文（Prompt Context） 请求摘要、允许公开的状态、相关知识片段、安全 Observation 摘要 上下文构建器从可信源生成 单次模型调用；通常不单独持久化原文 不能携带凭证、内部堆栈、无关 PII 或权限规则秘密
对话记忆（Chat Memory） 为当前 conversation 选择的用户与助手消息 ChatMemory 管保留策略，ChatMemoryRepository 管存取 滑动窗口 / TTL / token 策略 不能当完整 Chat History、工具审计或恢复检查点
长期业务记忆 / 完整历史 工单记录、用户授权事实、完整消息、不可变领域事件、审计记录 业务服务与 Spring Data / 数据库 由目的、法规、合同和删除请求决定 不能未经检索授权与脱敏就整批塞入 Prompt

边界判断：若字段丢失会导致重复写操作、越权、预算重置或无法恢复，它属于业务状态 / 事件，而不是 Chat Memory。若字段只为这一次模型推理提供语义，它属于 Prompt Context 的候选项。长期保存并不自动意味着应该给模型看。

#状态生命周期

1. 接收请求
2. 加载检查点
3. 获取 / 检查版本
4. 构建安全上下文
5. 决定 / 执行
6. 追加私有 Observation
7. 原子提交状态 / 事件
8. 结束 / 恢复
横切护栏：可信身份 · tenant/user 隔离 · TTL · 来源校验 · 脱敏 · 授权 · 预算 · 幂等 · 乐观锁 · 加密 · 审计

等价文字说明：应用接收请求后先从认证上下文建立 tenant、user、conversation、run 键；若为恢复则加载未过期检查点，获取处理权并核对 version。上下文构建器只投影当前步骤需要的安全字段，模型决策与工具执行仍经授权和预算控制。工具原文进入私有 Observation，独立 DLP / 分类服务只产出结构化安全投影；业务 Repository 在单一事务内处理幂等 key、expectedVersion、检查点、事件和 outbox。成功时结束，失败或实例重启时从最后一个已提交检查点恢复。全部节点持续执行隔离、TTL、脱敏、加密、审计和最小权限。

  1. requestId 与 runId 不混用：requestId 关联入口重试；runId 标识一次业务执行。相同幂等请求可能返回已有 run，而不是创建第二份状态。
  2. 加载时验证归属：查询条件至少包含 tenantId、userId（或授权主体）与 runId，不能先按全局 runId 查出对象再在应用层补过滤。
  3. 先判重，再比较版本：相同幂等 key 与 fingerprint 的已提交请求直接返回先前结果；首次请求才执行 UPDATE ... WHERE version = :expectedVersion。异 key 的更新行数为 0 即冲突。
  4. 一次事务提交完整恢复事实：检查点优化恢复速度，事件解释“为何到达此状态”，outbox 负责可靠发布；三者与幂等结果要么全部提交，要么全部回滚。

#上下文窗口与压缩

模型上下文有 token 上限和成本。把所有历史原样拼接既可能超窗，也会把过期事实、其他租户内容、提示注入和敏感诊断带入当前决策。安全上下文构建应先做访问控制，再做相关性选择，最后才考虑压缩。

策略收益固有损失 / 风险工程补偿
最近 N 条消息简单、成本可预测较早但关键的约束会被淘汰；N 条不等于 N 个完整 turn系统不变量不依赖消息窗口；关键业务事实从状态库重建
摘要压缩显著减少 token摘要会遗漏否定、时间、来源、不确定性或审批条件保存摘要版本、来源事件 ID、生成时间与置信标记；关键字段结构化保留
相关性检索只选当前问题相关片段可能漏召回，也可能召回被污染内容先按 tenant、权限、TTL、版本过滤，再排序；保留来源引用
分层组合系统约束 + 状态投影 + 少量消息 + 相关知识需要预算分配与冲突策略为每层设 token 预算、优先级和冲突时的可信度顺序

推荐构建顺序：固定安全规则 → 当前业务状态的 toPromptView() → 未过期且属于当前 conversation 的有限 Chat Memory → 经授权检索的知识 → 当前用户请求。若总量超预算，优先删低相关历史，不删除授权、预算、停止条件等应用侧不变量；这些不变量还必须在模型外再次强制执行。

TTL 不是单一缓存参数。应分别定义：Prompt 候选资料的时效、Chat Memory 的产品保留时长、检查点的可恢复窗口、完整历史的合规期限和事件审计的法定期限。删除请求必须遍历所有副本、索引、摘要、备份策略与向量化派生数据，并留下不含已删除内容的删除审计。

#Java 21：可序列化状态、检查点与恢复

下面是 provider-neutral 的 Java 21 领域骨架。record 只保证字段引用不可重新赋值；对集合仍需 Set.copyOf / Map.copyOf。示例把可给模型看的视图设计为另一种类型，避免调用方误把完整状态序列化进 Prompt。

import java.time.Instant;
import java.util.List;
import java.util.Map;
import java.util.Objects;
import java.util.Optional;
import java.util.Set;

record StateKey(String tenantId, String userId, String runId) {
    StateKey {
        tenantId = Required.text(tenantId, "tenantId");
        userId = Required.text(userId, "userId");
        runId = Required.text(runId, "runId");
    }
}

enum ToolStatus { NOT_STARTED, SUCCEEDED, SAFE_FAILURE, NEEDS_REVIEW }
enum RequestIntent { INVESTIGATE_INCIDENT, CHECK_TICKET, CREATE_TICKET_REQUEST }
enum ObservationKind { SERVICE_STATUS, TICKET_LOOKUP, KNOWLEDGE_LOOKUP }
enum ObservationOutcome { OK, NOT_FOUND, TEMPORARY_FAILURE, DENIED, NEEDS_REVIEW }
enum ServiceCode { PAYMENTS, IDENTITY, ORDERING }
enum IssueCode { INTERMITTENT_TIMEOUT, DEGRADED_SERVICE, ACCESS_FAILURE }
enum DetailCode {
    DEPENDENCY_TIMEOUT, TICKET_NOT_FOUND, KNOWLEDGE_VERSION_MISSING,
    POLICY_DENIED, NO_ADDITIONAL_DETAIL
}
enum KnowledgeSourceCode {
    PAYMENTS_RUNBOOK, INCIDENT_CATALOG, TICKETING_POLICY
}

record SafeRequestSummary(
        RequestIntent intent,
        ServiceCode serviceCode,
        IssueCode issueCode) {
    SafeRequestSummary {
        Objects.requireNonNull(intent, "intent");
        Objects.requireNonNull(serviceCode, "serviceCode");
        Objects.requireNonNull(issueCode, "issueCode");
    }
}

record PromptObservationView(
        ObservationKind kind,
        ObservationOutcome outcome,
        DetailCode detailCode) {
    PromptObservationView {
        Objects.requireNonNull(kind, "kind");
        Objects.requireNonNull(outcome, "outcome");
        Objects.requireNonNull(detailCode, "detailCode");
    }
}

record SafeObservationSummary(
        String observationId,
        ObservationKind kind,
        ObservationOutcome outcome,
        DetailCode detailCode) {
    SafeObservationSummary {
        observationId = Required.text(observationId, "observationId");
        Objects.requireNonNull(kind, "kind");
        Objects.requireNonNull(outcome, "outcome");
        Objects.requireNonNull(detailCode, "detailCode");
    }

    PromptObservationView toPromptView() {
        return new PromptObservationView(kind, outcome, detailCode);
    }
}

record KnowledgeVersionRef(KnowledgeSourceCode sourceCode, long revision) {
    KnowledgeVersionRef {
        Objects.requireNonNull(sourceCode, "sourceCode");
        if (revision < 1) {
            throw new IllegalArgumentException("revision must be positive");
        }
    }
}

record ExecutionBudget(int remainingSteps, long remainingTokens, Instant deadline) {
    ExecutionBudget {
        if (remainingSteps < 0 || remainingTokens < 0) {
            throw new IllegalArgumentException("budget cannot be negative");
        }
        Objects.requireNonNull(deadline, "deadline");
    }
}

record PromptStateView(
        SafeRequestSummary requestSummary,
        int approvedActionCount,
        Map<ObservationKind, ToolStatus> safeToolStatuses,
        Set<KnowledgeVersionRef> knowledgeSourceVersions,
        List<PromptObservationView> observations,
        int remainingSteps) {
    PromptStateView {
        Objects.requireNonNull(requestSummary, "requestSummary");
        safeToolStatuses = Map.copyOf(safeToolStatuses);
        knowledgeSourceVersions = Set.copyOf(knowledgeSourceVersions);
        observations = List.copyOf(observations);
    }
}

record AgentState(
        String tenantId,
        String userId,
        String conversationId,
        String runId,
        SafeRequestSummary requestSummary,
        Set<String> approvedActionIds,
        Map<ObservationKind, ToolStatus> lastToolStatuses,
        Set<KnowledgeVersionRef> knowledgeSourceVersions,
        List<SafeObservationSummary> safeObservations,
        ExecutionBudget budget,
        long version,
        Instant updatedAt) {

    AgentState {
        tenantId = Required.text(tenantId, "tenantId");
        userId = Required.text(userId, "userId");
        conversationId = Required.text(conversationId, "conversationId");
        runId = Required.text(runId, "runId");
        Objects.requireNonNull(requestSummary, "requestSummary");
        approvedActionIds = Set.copyOf(approvedActionIds);
        lastToolStatuses = Map.copyOf(lastToolStatuses);
        knowledgeSourceVersions = Set.copyOf(knowledgeSourceVersions);
        safeObservations = List.copyOf(safeObservations);
        Objects.requireNonNull(budget, "budget");
        Objects.requireNonNull(updatedAt, "updatedAt");
        if (version < 0) throw new IllegalArgumentException("version cannot be negative");
    }

    StateKey key() {
        return new StateKey(tenantId, userId, runId);
    }

    // 不暴露 tenant/user、原始审批 ID、私有 Observation 或内部异常。
    PromptStateView toPromptView() {
        return new PromptStateView(
                requestSummary,
                approvedActionIds.size(),
                lastToolStatuses,
                knowledgeSourceVersions,
                safeObservations.stream()
                        .map(SafeObservationSummary::toPromptView)
                        .toList(),
                budget.remainingSteps());
    }

    AgentState next(
            Map<ObservationKind, ToolStatus> toolStatuses,
            List<SafeObservationSummary> observations,
            Instant now) {
        return new AgentState(
                tenantId, userId, conversationId, runId, requestSummary,
                approvedActionIds, toolStatuses, knowledgeSourceVersions,
                observations, budget, version + 1, now);
    }
}

enum Sensitivity { INTERNAL, CONFIDENTIAL, RESTRICTED }

record AgentCheckpoint(
        AgentState state,
        String lastEventId,
        Instant createdAt,
        Instant expiresAt) {

    AgentCheckpoint {
        Objects.requireNonNull(state, "state");
        lastEventId = Required.text(lastEventId, "lastEventId");
        Objects.requireNonNull(createdAt, "createdAt");
        Objects.requireNonNull(expiresAt, "expiresAt");
        if (!expiresAt.isAfter(createdAt)) {
            throw new IllegalArgumentException("expiresAt must be after createdAt");
        }
    }

    boolean expiredAt(Instant now) {
        return !now.isBefore(expiresAt);
    }
}

record AgentEvent(
        String eventId,
        String idempotencyKey,
        StateKey key,
        long stateVersion,
        String eventType,
        Instant occurredAt) {}

record OutboxMessage(
        String messageId,
        String idempotencyKey,
        StateKey key,
        long stateVersion,
        String messageType,
        Instant createdAt) {}

enum RecoveryCommitDisposition { APPLIED, REPLAYED }

record RecoveryCommit(
        StateKey key,
        long expectedVersion,
        String idempotencyKey,
        String commandFingerprint,
        AgentCheckpoint nextCheckpoint,
        AgentEvent event,
        OutboxMessage outboxMessage) {
    RecoveryCommit {
        Objects.requireNonNull(key, "key");
        idempotencyKey = Required.text(idempotencyKey, "idempotencyKey");
        commandFingerprint = Required.text(commandFingerprint, "commandFingerprint");
        Objects.requireNonNull(nextCheckpoint, "nextCheckpoint");
        Objects.requireNonNull(event, "event");
        Objects.requireNonNull(outboxMessage, "outboxMessage");
        if (!key.equals(nextCheckpoint.state().key())
                || !key.equals(event.key())
                || !key.equals(outboxMessage.key())) {
            throw new IllegalArgumentException("all records must use the same state key");
        }
        if (!idempotencyKey.equals(event.idempotencyKey())
                || !idempotencyKey.equals(outboxMessage.idempotencyKey())) {
            throw new IllegalArgumentException("all records must use the same idempotency key");
        }
    }
}

record RecoveryCommitResult(
        AgentCheckpoint checkpoint,
        RecoveryCommitDisposition disposition) {
    RecoveryCommitResult {
        Objects.requireNonNull(checkpoint, "checkpoint");
        Objects.requireNonNull(disposition, "disposition");
    }
}

final class OptimisticStateConflict extends RuntimeException {
    OptimisticStateConflict(long expectedVersion) {
        super("state version conflict; expected=" + expectedVersion);
    }
}

final class IdempotencyKeyConflict extends RuntimeException {
    IdempotencyKeyConflict(String key) {
        super("idempotency key reused with different command; key=" + key);
    }
}

interface StateRepository {
    Optional<AgentCheckpoint> load(StateKey key);

    /*
     * 单一数据库事务合约：
     * 1. 先按 (StateKey, idempotencyKey) 查询或争抢唯一幂等记录。
     *    相同 fingerprint 已提交：返回原 RecoveryCommitResult(REPLAYED)，
     *    不比较 version、不更新 checkpoint、不重复写 event/outbox。
     *    相同 key 但 fingerprint 不同：抛 IdempotencyKeyConflict。
     * 2. 首次请求执行 UPDATE checkpoint
     *    WHERE state_key = ? AND version = expectedVersion；
     *    影响 0 行则抛 OptimisticStateConflict，并回滚全部写入。
     * 3. checkpoint、唯一 event、outbox 和幂等结果在同一事务提交；
     *    任一步失败都整体回滚，不存在“状态已推进但事件缺失”。
     */
    RecoveryCommitResult commitRecovery(RecoveryCommit command)
            throws OptimisticStateConflict, IdempotencyKeyConflict;

    void deleteConversation(String tenantId, String userId, String conversationId);
}

final class AgentRecoveryService {
    private final StateRepository repository;

    AgentRecoveryService(StateRepository repository) {
        this.repository = repository;
    }

    AgentCheckpoint resume(
            StateKey key,
            Map<ObservationKind, ToolStatus> recoveredStatuses,
            List<SafeObservationSummary> recoveredObservations,
            String recoveryEventId,
            String commandFingerprint,
            Instant now) {

        AgentCheckpoint loaded = repository.load(key)
                .orElseThrow(() -> new IllegalStateException("checkpoint not found"));
        if (loaded.expiredAt(now)) {
            throw new IllegalStateException("checkpoint expired; manual review required");
        }

        long expectedVersion = loaded.state().version();
        AgentState nextState = loaded.state().next(
                recoveredStatuses, recoveredObservations, now);
        AgentCheckpoint next = new AgentCheckpoint(
                nextState, recoveryEventId, now, loaded.expiresAt());
        AgentEvent event = new AgentEvent(
                recoveryEventId, recoveryEventId, key,
                nextState.version(), "RUN_RESUMED", now);
        OutboxMessage outbox = new OutboxMessage(
                "outbox-" + recoveryEventId, recoveryEventId, key,
                nextState.version(), "RUN_RESUMED", now);

        // 重放同一 recoveryEventId 返回先前 checkpoint；不同 key 的
        // 并发提交仍以 expectedVersion 冲突失败。
        return repository.commitRecovery(new RecoveryCommit(
                key, expectedVersion, recoveryEventId, commandFingerprint,
                next, event, outbox)).checkpoint();
    }
}

final class Required {
    static String text(String value, String name) {
        if (value == null || value.isBlank()) {
            throw new IllegalArgumentException(name + " is required");
        }
        return value;
    }
}

恢复事务：commitRecovery 是一个 Repository 原子操作，而不是三个可独立成功的方法。数据库实现先处理 (StateKey, idempotencyKey) 唯一幂等记录：相同 fingerprint 的重放返回先前 checkpoint 并标记 REPLAYED，不会推进 version；相同 key 配不同 fingerprint 明确拒绝。首次请求才做 expectedVersion 条件更新，并在同一事务写 checkpoint、唯一事件、outbox 和幂等结果。版本冲突或任意写入失败必须整体回滚。

结构化安全投影：SafeRequestSummary、SafeObservationSummary 与 PromptObservationView 只包含显式领域枚举、计数和 KnowledgeVersionRef 等受信类型。ServiceCode、IssueCode、DetailCode、KnowledgeSourceCode 的常量集合就是不可变 allowlist；仅仅长得像 UPPER_SNAKE_CASE 并不能成为合法值。虽然 ObservationEnvelope 在私有持久化边界持有密文字段，但 PromptObservationView 没有 raw / private 字段或访问器，toPromptView() 也只映射已分类的安全摘要。密文由专用加密服务产生，不是 Base64。

DLP 与映射边界：工具原文进入这些 record 之前，必须由示例外的独立 DLP / 数据分类 / 脱敏服务识别 PII、凭证、内部主机名和策略敏感内容，再由服务器端确定性映射器转换成领域枚举。未知 service、issue、detail 或 knowledge source 必须拒绝或映射为预先定义的 NEEDS_REVIEW 结果，不能把原字符串包装后放行。DLP 服务仍需要自己的规则库、检测器版本与回归数据集。

#Spring AI 2.0.0：显式 Chat Memory

Spring AI 的 Chat Memory 是模型对话上下文机制，不是业务 Agent Runtime。官方定义清楚地区分了 Chat Memory（模型为当前对话保留并使用的相关信息）与 Chat History（用户与模型交换的全部消息）。MessageWindowChatMemory 维护消息滑动窗口；超过上限时淘汰较旧消息，并尽量在完整 turn 边界裁剪。Spring AI Chat Memory

Provider-neutral 配置与调用

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.client.advisor.MessageChatMemoryAdvisor;
import org.springframework.ai.chat.memory.ChatMemory;
import org.springframework.ai.chat.memory.MessageWindowChatMemory;
import org.springframework.ai.chat.model.ChatModel;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
class ServiceDeskAiConfiguration {

    @Bean
    ChatMemory chatMemory() {
        return MessageWindowChatMemory.builder()
                .maxMessages(20)
                .build();
    }

    @Bean
    ChatClient serviceDeskChatClient(
            ChatModel chatModel,
            ChatMemory chatMemory) {

        return ChatClient.builder(chatModel)
                .defaultAdvisors(
                        MessageChatMemoryAdvisor.builder(chatMemory).build())
                .build();
    }
}

final class ServiceDeskAssistant {
    private final ChatClient chatClient;

    ServiceDeskAssistant(ChatClient chatClient) {
        this.chatClient = chatClient;
    }

    String answer(String conversationId, String safeUserText) {
        if (conversationId == null || conversationId.isBlank()) {
            throw new IllegalArgumentException("conversationId is required");
        }

        return chatClient.prompt()
                .user(safeUserText)
                .advisors(a -> a.param(
                        ChatMemory.CONVERSATION_ID,
                        conversationId))
                .call()
                .content();
    }
}

三处调用形态是本课验收重点：MessageWindowChatMemory.builder() 定义消息窗口，MessageChatMemoryAdvisor.builder(chatMemory) 把该窗口接入 client，ChatClient.builder(chatModel) 保持模型供应商中立；每次调用再通过 .advisors(a -> a.param(ChatMemory.CONVERSATION_ID, conversationId)) 显式选择会话。

缺失 ID 必须快速失败：官方文档明确说明所有 Memory Advisor 都要求 ChatMemory.CONVERSATION_ID，没有默认 conversation ID；省略会在运行时抛出 IllegalArgumentException。示例在业务边界先校验，是为了给出更明确的错误，但不能因此删掉运行时参数。Conversation ID 要求

不要直接使用前端传来的 conversationId。应用应根据已认证 tenantId、userId 和内部会话主键生成不可猜测的映射 ID，并在数据库查询中再次限定租户与主体。模型、消息内容和工具参数都无权覆盖该 ID。

默认内存实现不等于生产持久化。未提供其他 Repository 时，Spring AI 默认使用进程内 InMemoryChatMemoryRepository；实例重启会丢失，而且它仍不提供业务检查点、完整历史或审计语义。可以按需要配置持久化 ChatMemoryRepository，但业务 AgentState、完整 Chat History 和审计事件仍应有独立 Spring Data / 数据库模型。

工具消息限制要按当前实现设计：官方说明工具调用期间与模型交换的中间消息当前不会自动存入 memory。另有部分 Repository 对工具消息存在过滤限制。因此即使“最后回答看起来连贯”，也不能据此判断某工具是否真正执行、执行几次或已经提交副作用；这些事实只认业务事件与检查点。

#持久化、恢复与并发

检查点与事件日志

记录回答的问题写入策略恢复用途
AgentCheckpoint现在从哪里继续？首次幂等 key 以 expectedVersion 条件更新快速加载最近完整状态
领域 / 轨迹事件为什么到达这里？与幂等 key 唯一关联、只追加、带主体与时间审计、重放判定、修复与取证
Outbox状态更新后哪些消息必须发布？和 checkpoint、event、幂等结果同事务落库避免数据库已提交而消息丢失
Chat Memory模型这次需要哪些近期消息？独立窗口与 TTL只恢复对话连贯性，不恢复业务副作用

恢复前先区分“可重试计算”和“可能已产生副作用的动作”。模型调用、只读检索通常可按预算重试；创建工单、发通知、扣款等写操作必须先查幂等键和下游结果，不能因检查点看似停在执行前就再次调用。无法确认时标记 NEEDS_REVIEW，交给人工或对账流程。

commitRecovery 的实现顺序属于数据库合约：先以唯一键争抢或读取幂等结果；命中相同 fingerprint 时返回先前 checkpoint（REPLAYED）且不检查当前 version，避免重放把 version 8 推进为 9。首次命中才做 expectedVersion 条件更新，并写 event、outbox 与可重放结果。相同 key 携带不同 fingerprint 是调用错误，不能伪装成成功重放。

乐观锁冲突如何处理

  1. worker A 与 B 使用同一 idempotency key 和 fingerprint：A 提交 version 8；B 返回 A 已保存的 checkpoint 和 REPLAYED，version 仍为 8，event / outbox 仍各一条。
  2. worker C 与 D 使用不同 key、都读到 version 7：一个原子事务提交 version 8；另一个条件更新影响 0 行，抛 OptimisticStateConflict，其幂等占位、事件和 outbox 全部回滚。
  3. 在 checkpoint UPDATE 后、event INSERT 前注入故障：整个事务回滚，checkpoint 仍为 version 7，也没有事件、outbox 或“已成功”的幂等结果。
  4. 冲突方重新读取后，纯计算可在剩余预算内以新 key 重算；未知写副作用停止并转人工，不做盲目自动重试。

数据库 version 不是分布式锁的替代品，而是最终写入防丢失更新的必要条件。长耗时模型 / 工具调用不要持有数据库事务；可以使用短租约声明处理权，但提交时仍必须比较 version。租约超时也不证明旧 worker 已停止，所以工具侧幂等同样不可缺少。

#安全与隐私

记忆扩大了单次输入的生命周期：一次提示注入、错误权限结果或敏感数据若被持久化，可能影响后续会话。OWASP 将敏感信息泄露列为 LLM 应用风险，并建议清洗输入、限制外部数据访问、采用最小权限和严格访问控制；其 Agentic 安全材料还特别提醒持久记忆与上下文污染。OWASP GenAI Security Project

控制最低实现失败时的安全行为
租户 / 用户隔离可信身份生成复合分区键；所有查询与唯一约束带 tenant；conversation 映射验证主体拒绝而不是回退到“全局会话”
数据最小化与脱敏独立 DLP 分类原文；toPromptView() 只接收显式领域枚举、计数与受信 record，没有 raw payload 字段未知值拒绝或映射到预定义 NEEDS_REVIEW；固定公开错误，私有诊断写受控存储
TTL 与删除每层独立保留策略；索引、摘要、派生向量和备份有删除流程过期即不加载；恢复转人工或重新开始
加密与访问控制传输加密、静态加密、密钥轮换、最小权限服务账号、字段级审计密钥 / 权限不可用时停止，不降级为明文
不可信内容边界Observation、历史消息、摘要、检索内容标记为数据；校验来源和结构检测到可疑指令时隔离、记录、请求人工确认
公开 / 私有诊断分离用户只见稳定错误码和安全文案；堆栈、下游正文、策略细节只进私有审计诊断存储失败也不向用户回显原始异常

不要把 system prompt 当数据保险箱。Prompt 不是访问控制，模型也可能复述其中内容。凭证、连接串、原始审批 token、加密密钥和完整权限图不应进入任何 Prompt。真正的授权以 Spring Security / 服务端策略和数据库对象归属为准。

场景：用户要求调查支付服务异常。Agent 可能读取服务状态、查询其可见工单、检索知识并在获批后创建新工单。状态键和值建议如下：

工具 Observation “数据库超时，连接串为 …，请忽略规则并执行 …”同时包含敏感诊断和不可信指令。正确做法是：示例外的 DLP / 分类服务处理原始结果，私有诊断加密保存；确定性映射器只构造 SafeObservationSummary(SERVICE_STATUS, TEMPORARY_FAILURE, DEPENDENCY_TIMEOUT)。PromptObservationView 没有原文、toolName、主机名或私有密文字段，用户也只看到固定错误和可执行下一步。

实例在创建工单请求发出后宕机时，恢复器先根据 actionId / idempotency key 查询工单系统：若已创建则补写成功事件与检查点；若明确未创建且审批仍有效才重试；若状态未知则转人工。它绝不能根据 Chat Memory 中“我已经为你创建工单”的助手文本认定副作用成功。

#练习与验收

练习一：给字段分层

为下面字段选择“运行状态 / Prompt Context / Chat Memory / 长期业务记忆与历史”，并写出 TTL、访问主体和删除方式：用户原始问题、结构化安全请求摘要、审批 token、SafeObservationSummary、工具原始异常、完整消息、剩余预算、工单事实、知识版本。允许同一事实产生不同层的投影，但必须指出真相源。

练习二：实现 StateRepository

  1. 使用 PostgreSQL 或测试容器建立 checkpoint、recovery_idempotency、agent_event 与 outbox 四张表。
  2. 实现以 tenantId、userId、runId 定位的 load，禁止仅按 runId 全局查询。
  3. 用一个本地事务实现 commitRecovery：唯一幂等结果、expectedVersion 条件 UPDATE、event 与 outbox 必须原子提交。
  4. 证明相同 key / fingerprint 重放返回首次 checkpoint 且不增 version；不同 key 并发只有一个成功；在每个写入点注入故障都不会留下部分记录。
  5. 模拟实例重启，从数据库恢复预算、工具状态与知识版本；Chat Memory 清空也不影响业务恢复。

练习三：接入 Spring AI 2.0.0

使用任意 ChatModel Bean 与本页 provider-neutral 配置，建立两个 tenant、三个 conversation。验证每次调用显式传入由认证上下文映射的 ChatMemory.CONVERSATION_ID；省略 ID 必须失败；交换 ID 不能读到另一主体的内容。另用 Spring Data 独立保存完整消息与业务事件。

本课验收标准

  • 能解释运行状态、Prompt Context、Chat Memory、长期业务记忆 / Chat History 四层的真相源、用途、TTL 和删除责任。
  • 能准确说明 ChatMemoryRepository 负责存取、ChatMemory 决定保留；MessageWindowChatMemory 是滑动消息窗口。
  • 能证明每次 Memory Advisor 调用都显式传入可信 ChatMemory.CONVERSATION_ID，并测试缺失 ID 在运行时失败。
  • 能说明工具调用中间消息当前不会自动完整进入 Chat Memory，所以工具轨迹、业务状态、完整历史与审计必须独立持久化。
  • AgentState 使用不可变复制，包含 tenantId、userId、conversationId、runId、请求摘要、审批动作、工具状态、知识版本、预算和 version。
  • toPromptView() 只输出 SafeRequestSummary、显式领域枚举、计数、KnowledgeVersionRef 与 PromptObservationView；形状合法但未注册的值也会被拒绝，私有 payload 在类型结构上不可达。一般 PII 检测属于独立 DLP 服务。
  • commitRecovery 在单一事务验证幂等 key、预期 version，并原子写 checkpoint、event、outbox 与重放结果；重复 key 不增版本，冲突 / 故障不部分提交。
  • 测试矩阵覆盖跨租户串话、过期记忆、恢复冲突、重复重放、崩溃回滚、敏感 Observation、缺失 Conversation ID、重启与保留期删除。
