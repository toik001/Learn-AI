#Agent 开发学习主目录

面向 Java 开发者：先理解 Agent 的边界，再实现一个可观测、可限制、可测试的工具调用循环。

整理日期：2026-07-27；资料检索日期：2026-07-27。

#核心结论

  • Agent 不是某个模型或框架，而是“目标 + 决策 + 行动 + 反馈 + 状态”的系统循环。
  • LLM 只负责提出文本或结构化决策；工具的授权、执行、结果校验和审计必须由应用掌控。
  • 生产级 Agent 的起点不是多 Agent，而是单 Agent 的白名单工具、明确状态、步骤/时间/成本上限和可追踪日志。

#Agent 通用释义

Software Agent
感知环境、依据规则或策略采取行动以实现目标的软件实体。
AI Agent
决策策略部分使用机器学习或生成式模型的 Agent。
LLM Agent
以大语言模型承担理解、推理、规划或工具选择的 AI Agent。
Agentic System
由一个或多个 Agent、工具、状态、控制逻辑与人类协作组成的完整系统。

上述 Software Agent 边界与 NIST CSRC 术语表所述的 Agent 一致：软件程序能够与环境交互、接收信息，并为外部指定目标采取自主行动。本文在此基础上，将决策策略使用机器学习、生成式模型或大语言模型的情况分别称为 AI Agent 与 LLM Agent。NIST CSRC Glossary — Agent

这些是用于工程沟通的厂商无关工作定义。实现时应把“模型能提出请求”与“系统允许执行请求”分开：Spring AI 的官方说明同样强调，模型只能请求工具调用，客户端应用负责执行并回传结果。Spring AI Tool Calling

#Agent 不是什么

形态控制方式工具使用状态适用场景
普通聊天机器人单轮或固定提示词通常无，或由后端固定触发短对话历史问答、内容生成
固定工作流开发者预先编排分支步骤确定流程变量、持久化任务稳定业务流程、合规自动化
单 Agent模型在受限策略内选择下一步从白名单中结构化请求会话、Observation、任务进度调查、辅助操作、动态检索
多 Agent 系统协调器或协议分派角色各角色拥有不同受限能力共享或隔离的任务状态可独立分解、评审或并行的复杂任务

因此，带一个模型调用的程序不必然是 Agent；反过来，固定规则驱动的软件 Agent 也不必然是 AI Agent。先选最简单、最可审计的控制方式。

#核心组成

组成职责Java 中的典型边界
目标与请求定义用户意图、输入约束和成功条件AgentRequest、Bean Validation
上下文与状态保存已知事实、步骤、Observation 与预算AgentState、数据库/缓存
模型决策器输出最终答复或结构化工具请求AgentModel
工具注册表只暴露允许的工具和输入 schemaToolRegistry
运行时与护栏驱动循环、校验权限、限制预算、记录审计AgentRuntime、策略服务
环境与人返回 Observation，或对高风险操作批准/拒绝业务 API、队列、人工审批

#一次完整调用过程

用户目标
上下文组装
模型决策
工具调用
环境反馈
状态更新
循环判断
最终响应
护栏层：权限 · 校验 · 预算 · 人工审批 · 失败降级

等价文字说明：用户目标进入上下文组装；模型在可用工具和当前状态的约束下作出决策。若决策是最终答复，则直接输出；若是工具请求，运行时校验并执行工具，接收环境反馈（Observation），更新状态后回到模型决策。循环必须受最大步数、超时和成本预算约束。

  1. 将用户输入、系统规则、已知状态和当前可用工具组装为模型可见上下文。
  2. 模型返回两种互斥分支：final（直接产生最终答案）或 tool（请求名称与结构化参数）。
  3. 对于工具分支，应用先检查工具白名单、参数 schema、调用者权限、预算与是否需要人工批准；模型不能绕过这些检查。
  4. 工具与环境交互后产生 Observation；运行时将其连同步骤记录写入状态，供下一轮决策使用。
  5. 达到最终答复、最大步数、超时或成本预算时停止。失败则返回可解释的降级结果，而不是虚构工具结果。

这种“推理/行动交错，并从外部环境获取反馈”的模式可参考 ReAct 原始论文；论文讨论了交错轨迹如何帮助更新行动计划并处理异常。Yao et al., ReAct (2022)

#Java 开发者映射

可以把 Agent Runtime 看作一个受策略约束的应用服务编排器：Controller 接收请求，运行时维护事务外的任务状态，模型类似不可信的“决策建议者”，而工具像需要鉴权、参数校验、超时和审计的下游服务调用。模型输出不是可执行权限。

Agent 概念熟悉的 Java/Spring 类比不可忽略的差异
Tool call受 DTO 约束的服务调用调用意图来自概率模型，必须重新校验
Observation下游服务响应 / 领域事件应区分可信业务结果与不可信文本
AgentState会话状态 + Saga 上下文要控制上下文长度、敏感数据与可恢复性
GuardrailSpring Security、限流、熔断、审批同时约束模型输入、工具参数和输出动作

#最小 Java 实现

以下是 Java 21 的教学骨架，不依赖任何 SDK；真实项目可把 AgentModel 适配到模型 API，把 ToolRegistry 适配到 Spring Bean 或显式注册的业务客户端。

import java.util.ArrayList;
import java.util.List;
import java.util.Map;
import java.util.Objects;

record AgentRequest(String goal, String userId) {}
record ToolCall(String name, Map<String, Object> arguments) {}
record ToolResult(boolean success, String observation) {}
sealed interface ModelDecision permits FinalAnswer, ToolRequest {}
record FinalAnswer(String text) implements ModelDecision {
    FinalAnswer { Objects.requireNonNull(text, "text"); }
}
record ToolRequest(ToolCall toolCall) implements ModelDecision {
    ToolRequest { Objects.requireNonNull(toolCall, "toolCall"); }
}

interface AgentModel {
    ModelDecision decide(AgentRequest request, AgentState state, List<String> tools);
}

interface ToolRegistry {
    List<String> allowedToolNames();
    ToolResult execute(ToolCall call, String userId);
}

final class AgentState {
    private final List<String> observations = new ArrayList<>();
    void addObservation(String value) { observations.add(value); }
    List<String> observations() { return List.copyOf(observations); }
}

final class AgentRuntime {
    private static final int MAX_STEPS = 8;
    private static final String SAFE_TOOL_FAILURE_MESSAGE =
            "暂时无法取得所需信息，请稍后重试或联系人工支持。";
    private final AgentModel model;
    private final ToolRegistry tools;

    AgentRuntime(AgentModel model, ToolRegistry tools) {
        this.model = model;
        this.tools = tools;
    }

    String run(AgentRequest request) {
        AgentState state = new AgentState();
        for (int step = 0; step < MAX_STEPS; step++) {
            ModelDecision decision = model.decide(request, state, tools.allowedToolNames());
            switch (decision) {
                case FinalAnswer answer -> {
                    return answer.text();
                }
                case ToolRequest toolRequest -> {
                    ToolCall call = toolRequest.toolCall();
                    if (!tools.allowedToolNames().contains(call.name())) {
                        return "无法执行该请求：工具不在白名单中。";
                    }
                    ToolResult result = tools.execute(call, request.userId());
                    state.addObservation(result.observation()); // 仅供内部状态或私有 trace 使用
                    if (!result.success()) return SAFE_TOOL_FAILURE_MESSAGE;
                }
            }
        }
        return "已达到最多 8 步限制；请缩小目标或由人工继续处理。";
    }
}

最小代码刻意省略了真实的超时、预算计量、JSON Schema 校验、审批和持久化；它展示的边界是：模型决定“请求什么”，运行时决定“是否以及如何执行”。工具返回的 Observation 可能包含内部诊断、敏感信息或不可信外部文本，只能保留在 Agent 内部状态或经过访问控制的私有日志与 trace 中。面向用户的公开错误文案必须来自固定白名单；示例中的 SAFE_TOOL_FAILURE_MESSAGE 不拼接 Observation，私有诊断与公开错误文本必须严格分离。

#主学习路线

1. Agent 基础概念与边界 已建设

目标：区分 Agent、聊天、工作流与 Agentic System。
关键问题：何时不该用 Agent？
Java 实践：为需求写出目标、状态、工具、护栏四栏设计。
验收：能解释一次工具调用为何必须由应用执行。

2. 模型 API、结构化输出与 Tool Calling 已建设

目标：让模型输出可校验的决策。
关键问题：如何区分文本答复和工具请求？
Java 实践：用 sealed interface 与 record 表达互斥的 ModelDecision 分支和工具参数。
验收：拒绝未知工具与不合法参数。

3. 状态、上下文与记忆 已建设

目标：管理会话事实、Observation 与长期记忆。
关键问题：哪些信息可进上下文，哪些必须脱敏或过期？
Java 实践：实现可序列化的 AgentState。
验收：中断后能恢复且不泄露敏感数据。

4. 知识检索与 RAG 已建设

目标：把检索结果作为受引用约束的上下文。
关键问题：检索失败时如何诚实降级？
Java 实践：实现检索工具及来源记录。
验收：答案能追溯到召回文档。

5. 规划、反思与任务分解 已建设

目标：将复杂目标拆为可验证步骤。
关键问题：反思何时有用，何时只会增加成本？
Java 实践：加入计划状态与步骤预算。
验收：失败步骤可定位、可重试或可转人工。

6. 多 Agent 协作与编排 已建设

目标：只在角色边界明确时引入协作。
关键问题：共享状态如何避免冲突？
Java 实践：实现协调器与角色专属工具集。
验收：单 Agent 基线与协作方案可比较。

7. 评测、安全、权限与成本控制 已建设

目标：把正确性、安全性和成本变成可测指标。
关键问题：谁有权执行不可逆操作？
Java 实践：增加策略校验、审计和 token/调用预算。
验收：越权、超时、超预算与工具故障都有测试。

8. Java 生产部署、可观测性与故障恢复 已建设

目标：交付可运维的 Agent 服务。
关键问题：如何重放一次失败调用？
Java 实践：接入日志、指标、trace、重试与恢复队列。
验收：能用调用记录定位一次失败并安全恢复。

#第一个实践项目

带白名单城市与超时控制的天气工具 Agent

目标：用户以自然语言询问天气；模型只能请求 weather 工具，应用只接受预设城市，给工具调用配置超时，并将结果回传模型或安全降级。

  • 结构化参数：工具输入使用 { city: string }，由应用校验而非相信模型文本。
  • 工具白名单：运行时只注册 weather，禁止任意 URL、Shell 或数据库写入能力。
  • 循环限制：最多 8 步；到达上限直接停止并返回可理解信息。
  • 可追踪记录：为每步保存 requestId、工具名、脱敏参数、耗时、结果状态和降级原因。
  • 错误降级：城市不在白名单、超时、服务 5xx 或模型请求异常时，明确说明不能取得实时结果。
  • 单元测试：覆盖合法城市、越权城市、未知工具、超时、工具失败与第 8 步上限。
