#Agent 规划、反思与任务分解

模型可以提出候选步骤，但不能批准自己的计划。生产级规划的核心不是“想得更久”，而是把目标转换为一个经 DAG、工具权限、风险和预算校验的版本化执行计划，并让每一步都可暂停、审计、重试、补偿或转人工。

本文使用 Java 21、Spring AI 2.0.0 与 Spring Boot 4.0.x / 4.1.x，保持模型供应商中立。整理日期与官方资料检索日期：2026-07-27。

学习路径： 核心结论 · 目标与产物 · 执行策略 · 选择方法 · 状态机 · 有限反思 · Java 21 · Spring AI · 校验执行 · 服务台案例 · 测试策略 · 练习与验收 · 参考资料

#核心结论

  • 能用固定工作流解决，就不要先上动态规划。步骤稳定、分支有限、写操作风险高的流程更适合由代码显式编排；动态计划只在任务结构确实随观察变化时增加价值。
  • 模型输出只是候选计划。结构化 JSON 或 Java record 只解决形状与解析问题，不证明依赖无环、工具存在、调用获授权、估算可信或写操作安全。业务 PlanValidator 必须用可信工具目录、主体权限和服务端预算重新计算并拒绝违规计划。
  • 执行计划是版本化 DAG，不是一段自然语言。每步必须有稳定 ID、依赖、工具、输入引用、超时、最大尝试次数、风险、审批要求、幂等键、补偿策略和证据；只有全部依赖成功的步骤才可进入 READY。
  • 执行器必须持久化每次状态转换。READY → RUNNING → SUCCEEDED / FAILED_* 由带期望版本的原子更新完成；先持久化意图，再调用工具，再保存 Observation 摘要与外部引用，才能在崩溃后安全恢复。
  • 重试、补偿和重规划不是同一件事。瞬时只读失败可有限重试；不可重试或语义失败需要重规划或转人工；已产生外部副作用时只能调用事先登记、获授权且幂等的补偿动作，不能让模型临时发明“反向操作”。
  • 反思是有成本的可选层。Reflexion 研究显示语言反馈和情景记忆可在若干基准上改善后续尝试，但它不保证生产正确性。反思必须由失败证据触发，并受轮次、时间、token、工具调用和总成本限制；达到上限立即停止并转人工。Reflexion 原论文
  • Spring AI 不是通用 Planner 或工作流引擎。Spring AI 2.0.0 的 ChatClient 与 Structured Output 可帮助生成结构化候选；Planner 策略、DAG 校验、审批、持久状态机、Executor、补偿和反思循环均由应用实现。

#四种执行策略：反思是可选增强层

这里把“固定工作流、单步工具循环、ReAct、计划后执行”视为四种执行策略；反思不是第五种执行器，而是仅在有可判定反馈时叠加到 ReAct 或计划执行上的有限改进层。

策略控制方式适用场景主要收益主要代价 / 风险
固定工作流
Deterministic workflow		代码预定义节点、分支和错误路径流程稳定、合规严格、写操作多、输入变化有限可预测、低延迟、易测试和审计难处理结构未知的新任务；变更需要发版
单步工具循环模型每轮选择至多一个获准工具，应用执行后返回 Observation目标简单，只需一两次查询，下一步由最新结果决定实现小、上下文新鲜、无需完整计划容易重复调用；必须限制轮数、工具数与总时长
ReAct推理 / 动作 / 观察交错，持续更新局部策略环境信息逐步揭示、动作结果影响下一步能边查边改路径；论文在问答和交互基准上报告改进轨迹更长、更贵，可能循环；研究结果不等于安全保证
计划后执行
Plan-then-execute		先产出显式 DAG，经校验审批后按 ready steps 执行多步骤、有依赖、可并行、需审计 / 审批 / 恢复全局可见、可预算、可暂停、可恢复初始计划可能过时；需要版本化重规划
有限反思层失败后基于可验证反馈生成一次修正建议，再重新校验有测试、编译器、规则检查或人工反馈等明确评价信号可能修复遗漏步骤或错误假设额外模型调用、延迟和自我确认偏差；必须有硬上限

论文边界：ReAct 论文研究了让模型交错生成推理轨迹与任务动作，并在 HotpotQA、FEVER、ALFWorld 和 WebShop 等实验中比较基线；Plan-and-Solve 论文研究的是先划分子任务、再依计划求解，以缓解 Zero-shot-CoT 的漏步骤问题。两者提供方法证据，不证明它们在你的工具、权限、数据和 SLA 下必然更好。ReAct · Plan-and-Solve

#何时需要规划

任务特征低中高选择建议
步骤复杂度一次查询 / 一次回答2～4 步、少量分支多依赖、并行、部分完成低：单步；中：固定工作流或 ReAct；高：显式 DAG
环境不确定性输入完整、工具结果稳定需一次观察补齐信息结果持续改变后续路径不确定性越高越需要增量观察；不要一次性锁死长计划
副作用风险纯只读、易撤销内部低风险变更写入工单、生产配置、资金 / 权限风险越高越偏向固定流程、独立审批和人工门；不是“更自主”
延迟要求允许秒到分钟数秒交互级低延迟延迟越敏感，越少规划 / 反思模型调用；优先缓存或确定性路径
成本预算充足且价值高有明确上限严格受限预算严格时固定步骤与小模型分类优先；反思不是免费重试

五个判断问题

  1. 执行前是否已知全部步骤，且分支数量有限？若是，优先固定工作流。
  2. 是否只有一个当前可行动作，执行后才能知道下一步？若是，采用受限单步循环。
  3. 是否存在三个以上有依赖的步骤、可并行分支、审批点或恢复要求？若是，建立显式 DAG。
  4. 是否有客观评价信号能指出哪里错了？没有测试、规则或人工反馈时，不要启动自我反思。
  5. 失败后继续尝试的期望价值是否高于额外延迟、token、工具调用与副作用风险？否则直接安全失败或转人工。

等价文字说明：应用先从认证态、持久状态和业务配置读取目标与可信约束，再允许模型输出结构化候选计划。业务校验器拒绝循环、缺失依赖、重复步骤、未知或越权工具、不安全写操作和超预算计划；高风险步骤由计划外的独立审批服务确认。只有全部依赖成功的步骤才能成为 READY。Executor 用期望版本持久化 RUNNING，随后执行已登记工具；完成后验证 Observation、保存摘要 / 外部引用和预算消耗。若目标完成则终止；若新证据使计划失效则产生版本加一的新计划并重新走完整校验；无法安全继续、预算耗尽或人工拒绝时转人工。租户授权、版本、乐观锁、各类预算、有限重试、幂等、补偿、审计与反思上限横切全流程。

DAG 与 ready set

DAG（Directed Acyclic Graph，有向无环图）让“先做什么”成为可检查的数据。边 A → B 表示 B 依赖 A；当且仅当 B 的所有依赖都为 SUCCEEDED，B 才能进入 READY。无依赖步骤可并行，但并行执行仍要共享原子预算和互斥资源锁。拓扑排序无法访问全部节点时即存在环，计划在任何工具调用前失败。

状态进入条件允许的下一状态必须保存的证据

幂等、重试、补偿与重规划

  • 幂等：读取天然可重试；写入仅在工具契约明确支持幂等键、业务键或 compare-and-set 时有限重试。HTTP 方法名称不等于业务幂等，重复 POST 创建工单尤其危险。
  • 重试：只处理 429、连接重置、明确 5xx 等瞬时技术失败，并使用指数退避、抖动、最大尝试次数和 deadline。校验失败、403、参数错误、策略拒绝和业务冲突不可重试。
  • 补偿：补偿不是数据库回滚，而是新的业务动作。它必须预先登记、再次鉴权、可审计并处理补偿自身失败；例如“关闭刚创建的重复工单”不等于删除审计记录。
  • 重规划：当 Observation 否定关键假设、依赖永久不可用、目标被用户合法修改，或剩余图不再可达时，保留旧版本事件，创建 planVersion + 1 并重新校验。不得原地改写已经执行过的步骤。
  • 转人工：权限不足、预算耗尽、审批拒绝、补偿失败、反思达上限、未知副作用或连续冲突时停止自动执行，提交最小必要证据与明确待决定事项。

#反思的收益与成本

Reflexion 论文提出用语言形式的反馈和情景记忆影响后续尝试，而不是更新模型权重，并在顺序决策、编程和语言推理任务上报告相对基线的改进。这个研究结论适合启发“失败后生成修正建议”，但不能推出模型能够可靠地审计自己，更不能替代外部测试、权限策略或人工审批。

何时允许反思何时禁止继续反思每轮必须产出
测试失败给出确定断言；编译器 / schema / 规则引擎给出可定位错误；工具 Observation 与计划假设矛盾；人工给出具体反馈没有新证据；只是“再想一遍”；需要扩大权限；写操作结果未知；同一失败重复；任一预算耗尽；达到 MAX_REFLECTION_ROUNDS引用具体 evidence ID、指出失效假设、提出最小计划 diff、估算新增预算、说明是否需要新审批
 
record ReflectionBudgetRequest(
        long wallClockMillis,
        long modelTokens,
        int toolCalls,
        long costMicros) {}

interface ReflectionBudgetGate {
    boolean tryReserveReflection(
            java.util.UUID runId,
            long expectedBudgetVersion,
            ReflectionBudgetRequest request);
}

final class BoundedReflectionPolicy {
    static final int MAX_REFLECTION_ROUNDS = 2;
    static final long MIN_REFLECTION_COST_MICROS = 5_000;
    private static final ReflectionBudgetRequest MINIMUM_RESERVATION =
            new ReflectionBudgetRequest(2_000, 800, 1,
                    MIN_REFLECTION_COST_MICROS);

    ReflectionDecision decide(
            java.util.UUID runId,
            long expectedBudgetVersion,
            int completedRounds,
            boolean hasNewVerifiableEvidence,
            boolean sideEffectOutcomeKnown,
            RemainingBudget remaining,
            ReflectionBudgetGate budgetGate) {

        if (completedRounds >= MAX_REFLECTION_ROUNDS) {
            return ReflectionDecision.ESCALATE_LIMIT_REACHED;
        }
        if (!hasNewVerifiableEvidence || !sideEffectOutcomeKnown) {
            return ReflectionDecision.ESCALATE_UNSAFE_OR_NO_NEW_EVIDENCE;
        }
        if (remaining.wallClockMillis() < 2_000
                || remaining.tokens() < 800
                || remaining.toolCalls() < 1
                || remaining.costMicros()
                        < MIN_REFLECTION_COST_MICROS) {
            return ReflectionDecision.ESCALATE_BUDGET_EXHAUSTED;
        }
        // 预算版本校验与四个维度的扣减必须是一个原子 compare-and-set。
        if (!budgetGate.tryReserveReflection(
                runId, expectedBudgetVersion, MINIMUM_RESERVATION)) {
            return ReflectionDecision.ESCALATE_BUDGET_EXHAUSTED;
        }
        return ReflectionDecision.ALLOW_ONE_ROUND;
    }
}

反思文本本身是不可信候选，不直接写入长期记忆或执行。它只能提出新计划 diff；应用重新执行完整的 DAG、权限、预算和审批校验。在调用反思模型之前，tryReserveReflection 必须以 expectedBudgetVersion 原子检查并预占本轮最小 wall-clock、token、tool-call 与 cost；任一不足或并发抢占失败都不调用模型，直接转人工。完成后用实际 usage 结算 reservation，未使用额度按预算策略释放；失败的模型调用仍计入已消耗成本。持久记录反思轮次、触发 evidence、输入 / 输出摘要、token、cost 与延迟，但默认不把完整内部推理轨迹写入普通日志或展示给用户。

#Java 21：不可变计划模型

下面是供应商中立的 Java 21 领域模型。record 提供不可变载体；所有集合在紧凑构造器中复制，避免计划通过外部引用被悄悄修改。模型生成的是 CandidatePlan，只有业务校验器能产生 ExecutionPlan。

import java.time.Duration;
import java.time.Instant;
import java.util.List;
import java.util.Map;
import java.util.Optional;
import java.util.Set;
import java.util.UUID;

enum StepStatus {
    PLANNED, WAITING_APPROVAL, READY, RUNNING,
    SUCCEEDED, FAILED_RETRYABLE, FAILED_FINAL,
    COMPENSATING, COMPENSATED, BLOCKED,
    HUMAN_REJECTED, ESCALATED
}

enum ToolRisk { READ_ONLY, LOW_RISK_WRITE, HIGH_RISK_WRITE }

record PlanningInput(
        String objective,

        String principalId,

        List<String> allowedToolNames) {
    PlanningInput {
        allowedEvidenceIds = List.copyOf(allowedEvidenceIds);

    }
}

        String stepId,
        int attempt,
        String observationDigest,

        long consumedTokens,
        int consumedToolCalls,

        externalReferences = List.copyOf(externalReferences);
    }
}

record BudgetReservation(
        long wallClockMillis,
        long modelTokens,
        int toolCalls,
        long costMicros) {}

record AuthorizedAttempt(
        int attempt,
        String reservationId,
        String idempotencyKey) {}

interface Planner {
    CandidatePlan propose(PlanningInput input);
}

interface StepExecutor {
    StepExecutionResult executeReadyStep(
            UUID planId, long expectedPlanVersion, String stepId);
}

arguments 只是候选参数；执行前还要按工具自己的输入 record / Bean Validation 转换，不能把任意 Map 直接交给反射、HTTP 客户端、SQL、Shell 或 URL。idempotencyKey、risk、approval 与 compensation 由工具目录和服务器规则派生，不能采信模型自报。

业务 PlanValidator：从候选到可执行计划

final class PlanValidator {
    private static final int MAX_ATTEMPTS_PER_STEP = 3;
    private static final Duration MAX_STEP_TIMEOUT = Duration.ofSeconds(30);

    private final ToolCatalog tools;
    private final ToolAuthorization authorization;
    private final WriteIntentService writeIntents;
    private final Clock clock;

    PlanValidator(
            ToolCatalog tools,
            ToolAuthorization authorization,
            WriteIntentService writeIntents,
            Clock clock) {
        this.tools = tools;
        this.authorization = authorization;
        this.writeIntents = writeIntents;
        this.clock = clock;
    }

    ExecutionPlan validate(
            CandidatePlan candidate,
            PlanningInput input,
            ExecutionBudget trustedBudget) {

        if (!candidate.objective().equals(input.objective())) {
            throw new InvalidPlan("objective changed");
        }
        if (candidate.steps().isEmpty()
                || candidate.steps().size() > trustedBudget.maxSteps()) {
            throw new InvalidPlan("step budget exceeded");
        }

        Map<String, CandidateStep> byId = new HashMap<>();
        for (CandidateStep step : candidate.steps()) {
            if (step.stepId() == null || step.stepId().isBlank()
                    || byId.putIfAbsent(step.stepId(), step) != null) {
                throw new InvalidPlan("blank or duplicate step id");
            }
        }
        for (CandidateStep step : candidate.steps()) {
            if (!byId.keySet().containsAll(step.dependsOn())) {
                throw new InvalidPlan("missing dependency");
            }
            if (step.dependsOn().contains(step.stepId())) {
                throw new InvalidPlan("self dependency");
            }
        }
        rejectCycles(byId);

        UUID planId = UUID.randomUUID();
        long planVersion = 1L;
        long estimatedWallClockMillis = 0;
        long estimatedTokens = 0;
        int estimatedToolCalls = 0;
        long estimatedCostMicros = 0;
        List<PlanStep> normalized = new ArrayList<>();
        for (CandidateStep step : candidate.steps()) {
            ToolDescriptor tool = tools.find(step.toolName())
                    .orElseThrow(() -> new InvalidPlan("unknown tool"));
            if (!input.allowedToolNames().contains(tool.name())) {
                throw new InvalidPlan("tool outside run-scoped allowlist");
            }
            authorization.requireAllowed(
                    input.tenantId(), input.principalId(), tool.name());

            if (step.maxAttempts() < 1
                    || step.maxAttempts() > MAX_ATTEMPTS_PER_STEP) {
                throw new InvalidPlan("invalid retry budget");
            }
            Duration timeout = Duration.ofMillis(step.timeoutMillis());
            if (timeout.isZero() || timeout.isNegative()
                    || timeout.compareTo(MAX_STEP_TIMEOUT) > 0) {
                throw new InvalidPlan("invalid step timeout");
            }
            if (tool.risk() != ToolRisk.READ_ONLY
                    && !tool.supportsIdempotencyKey()) {
                throw new InvalidPlan("unsafe write without idempotency");
            }
            if (tool.risk() != ToolRisk.READ_ONLY
                    && !authorization.mayWrite(
                            input.tenantId(), input.principalId(), tool.name())) {
                throw new InvalidPlan("unauthorized write");
            }

            // 成本来自可信工具目录，不采信模型的低估值。
            long serverTokens = Math.max(
                    step.estimatedTokens(), tool.minimumTokenEstimate());
            int serverCalls = Math.max(
                    step.estimatedToolCalls(), tool.minimumToolCalls());
            long worstCaseMillis = Math.multiplyExact(
                    timeout.toMillis(), step.maxAttempts());
            long serverCostMicros = Math.multiplyExact(
                    tool.minimumCostMicros(), serverCalls);
            estimatedWallClockMillis = Math.addExact(
                    estimatedWallClockMillis, worstCaseMillis);
            estimatedTokens = Math.addExact(estimatedTokens, serverTokens);
            estimatedToolCalls = Math.addExact(estimatedToolCalls, serverCalls);
            estimatedCostMicros = Math.addExact(
                    estimatedCostMicros, serverCostMicros);

            Map<String, Object> normalizedArguments =
                    tool.validateAndNormalize(step.arguments());
            String canonicalRequestFingerprint =
                    tool.canonicalRequestFingerprint(normalizedArguments);
            String intentId = tool.risk() == ToolRisk.READ_ONLY
                    ? ""
                    : writeIntents.issueOrCarryForward(
                            input.tenantId(), planId, planVersion,
                            step.stepId(), canonicalRequestFingerprint);
            String idempotencyKey = tool.risk() == ToolRisk.READ_ONLY
                    ? ""
                    : IdempotencyKeys.compose(
                            input.tenantId(), planId, intentId,
                            step.stepId(), canonicalRequestFingerprint);
            normalized.add(new PlanStep(
                    step.stepId(), step.description(), tool.name(),
                    normalizedArguments,
                    Set.copyOf(step.dependsOn()), timeout, step.maxAttempts(),
                    tool.risk(), tool.requiresApproval(), intentId,
                    canonicalRequestFingerprint, idempotencyKey,
                    tool.compensationTool().orElse(""), StepStatus.PLANNED));
        }
        if (estimatedWallClockMillis > trustedBudget.maxWallClockMillis()
                || estimatedTokens > trustedBudget.maxModelTokens()
                || estimatedToolCalls > trustedBudget.maxToolCalls()
                || estimatedCostMicros > trustedBudget.maxCostMicros()) {
            throw new InvalidPlan("execution budget exceeded");
        }

        return new ExecutionPlan(
                planId, planVersion, input.objective(),
                List.copyOf(normalized), trustedBudget, 0, clock.instant());
    }

    private static void rejectCycles(Map<String, CandidateStep> byId) {
        Map<String, Integer> indegree = new HashMap<>();
        Map<String, List<String>> outgoing = new HashMap<>();
        byId.keySet().forEach(id -> {
            indegree.put(id, 0);
            outgoing.put(id, new ArrayList<>());
        });
        byId.values().forEach(step -> step.dependsOn().forEach(parent -> {
            outgoing.get(parent).add(step.stepId());
            indegree.merge(step.stepId(), 1, Integer::sum);
        }));

        ArrayDeque<String> ready = new ArrayDeque<>();
        indegree.forEach((id, degree) -> {
            if (degree == 0) ready.add(id);
        });
        int visited = 0;
        while (!ready.isEmpty()) {
            String id = ready.remove();
            visited++;
            for (String child : outgoing.get(id)) {
                if (indegree.merge(child, -1, Integer::sum) == 0) {
                    ready.add(child);
                }
            }
        }
        if (visited != byId.size()) {
            throw new InvalidPlan("dependency cycle");
        }
    }
}

示例省略了参数 schema 类和异常定义，但校验顺序不能省：先做结构与 DAG，再解析可信工具描述、鉴权并归一化参数，最后按服务端估算累计预算。实际系统还应校验 wall-clock / cost 上界、互斥资源、租户数据引用、证据来源、并行宽度和补偿图，并给 PlanValidator 与工具目录自身加版本号。

持久化 StepExecutor

final class PersistingStepExecutor implements StepExecutor {
    private final PlanRepository plans;
    private final ToolGateway tools;
    private final ApprovalService approvals;
    private final FailureClassifier failures;

    // constructor 省略

    @Override
    public StepExecutionResult executeReadyStep(
            UUID planId, long expectedPlanVersion, String stepId) {

        PlanSnapshot snapshot = plans.load(planId);
        PlanStep step = snapshot.requireStep(stepId);
        if (snapshot.planVersion() != expectedPlanVersion
                || step.status() != StepStatus.READY
                || !snapshot.allDependenciesSucceeded(step)) {
            return StepExecutionResult.notClaimed("stale or not ready");
        }
        if (step.approvalRequired()
                && !approvals.isApproved(planId, expectedPlanVersion, stepId)) {
            plans.transition(planId, expectedPlanVersion, stepId,
                    StepStatus.READY, StepStatus.WAITING_APPROVAL,
                    "approval-required");
            return StepExecutionResult.waitingForApproval();
        }
        BudgetReservation requested = snapshot.requiredReservation(step);
        java.util.Optional<AuthorizedAttempt> authorized =
                plans.claimAndReserve(
                        planId,
                        expectedPlanVersion,
                        stepId,
                        StepStatus.READY,
                        requested,
                        step.idempotencyKey());
        if (authorized.isEmpty()) {
            // 版本 / 状态已变化，或预算不足：没有状态 claim，也没有预算扣减。
            return StepExecutionResult.notClaimed(
                    "stale, already claimed, or budget exhausted");
        }
        AuthorizedAttempt claim = authorized.orElseThrow();
        try {
            ToolObservation observation = tools.execute(
                    step.toolName(), step.arguments(),
                    claim.idempotencyKey(), step.timeout());
            StepEvidence evidence = verifyAndSummarize(
                    snapshot, step, claim.attempt(), observation);
            plans.completeWithEvidence(
                    planId, expectedPlanVersion, stepId,
                    claim.reservationId(), evidence, observation.usage());
            return StepExecutionResult.succeeded(evidence);
        }
        catch (RuntimeException failure) {
            FailureClass kind = failures.classify(failure);
            boolean retrySafe = step.risk() == ToolRisk.READ_ONLY
                    || !step.idempotencyKey().isBlank();
            boolean attemptsRemain = claim.attempt() < step.maxAttempts();
            boolean budgetRemains = plans.mayRetry(
                    planId, claim.reservationId());

            if (kind == FailureClass.TRANSIENT
                    && retrySafe && attemptsRemain && budgetRemains) {
                plans.failRetryableThenScheduleReady(
                        planId, expectedPlanVersion, stepId,
                        claim.reservationId(),
                        privateDiagnosticCode(failure));
                return StepExecutionResult.retryScheduled();
            }
            plans.failFinalAndEscalate(
                    planId, expectedPlanVersion, stepId,
                    claim.reservationId(),
                    privateDiagnosticCode(failure));
            return StepExecutionResult.escalated();
        }
    }
}

claimAndReserve 必须在同一个数据库事务中同时完成两件事：用 planId + expectedPlanVersion + stepId + expectedStatus compare-and-set 将 READY 改为 RUNNING 并递增 attempt；在同一行锁 / 事务内检查并预占 wall-clock、token、tool-call 与 cost 预算。两者要么一起成功并返回唯一 AuthorizedAttempt，要么一起失败且不产生任何预算扣减。Executor 必须检查返回值，只有持有该授权 attempt 的 worker 才能调用工具；不能先预占预算再 claim，也不能忽略 claim 失败。工具调用仍无法与数据库跨系统原子提交，因此写工具还必须使用外部系统可识别的幂等键，并在恢复时先查询外部结果，再决定是否重放。

写操作幂等键绑定逻辑意图，而不是只绑定步骤名。服务端先对工具名、目标资源和归一化参数做 canonical serialization / hash，得到 canonicalRequestFingerprint；再组合 tenant、planId、intentId、stepId 与 fingerprint。新计划的默认 intentId 含 planVersion，因此不同重规划意图不会因复用 S6 之类的 stepId 被误去重；同一 attempt 的有限重试从持久 AuthorizedAttempt 复用完全相同的 key。只有当新版本明确继续同一个已批准逻辑写意图，且目标、动作、canonical fingerprint 均未变化时，应用 WriteIntentService 才可从持久状态继承同一 intentId，以便跨版本查证 / 去重；模型不能请求继承，审批仍按新 planVersion 重新检查。目标或 payload 任何变化都签发新 intentId。

示例预算与人工门

  • 最多 8 步、总 wall-clock 60 秒、每步 5～30 秒、最多 10 次工具调用、模型输入输出合计 12,000 tokens、反思最多 2 轮。
  • 只读查询单步最多 2 次；写步骤最多 1 次业务提交。网络不确定时只用相同幂等键查证结果，不产生第二个逻辑写入。
  • 创建 / 更新工单必须由当前 tenant 的支持人员审批精确 diff；审批过期、主体变化或 planVersion 变化均重新审批。
  • 公开响应只给出“诊断未完成 / 等待审批 / 已转人工”和安全引用；原始异常、内部 URL、完整 Observation 与策略细节进入受限诊断存储。

同一步骤并发 claim两个 worker 同时对同一 READY 步骤调用 claimAndReserve只返回一个 AuthorizedAttempt、只产生一笔预算 reservation 和一次工具调用；失败 worker 既不执行也不扣预算
幂等意图与重规划同 tenant / stepId 在 v1、v2 使用不同 payload；另测同 intentId + 相同 fingerprint 的恢复重试不同逻辑写意图得到不同 key；同一获准意图的 retry / 查证复用完全相同 key，不重复写入
部分完成S1 成功产生副作用，S2 永久失败仅评估预注册补偿；原步骤证据保留，补偿独立审计
人工拒绝审批服务返回 reject步骤为 HUMAN_REJECTED，依赖写步骤永不 READY，不能反思绕过
崩溃恢复外部写成功后、数据库保存 evidence 前进程崩溃恢复器用同一幂等键查询外部状态，不重复创建对象
计划版本冲突worker 执行 v1 时已创建 v2compare-and-set 影响 0 行，v1 工具不调用，旧审批不复用

关键性质测试：对任意通过验证的计划，所有依赖 ID 均存在、图可拓扑排序、所有工具均在 allowlist、所有写步骤具备审批与幂等策略，按可信成本重算后不超过预算；对任意状态轨迹，不出现 PLANNED → SUCCEEDED、HUMAN_REJECTED → RUNNING 或终态重新执行。故障注入覆盖进程终止、超时后的迟到响应、重复消息与数据库乐观锁冲突。

#练习与验收

练习：实现受治理的服务台计划执行

  1. 用 Java 21 实现本页 records、Planner、PlanValidator 与内存 PlanRepository；先写循环、缺失依赖、重复步骤、未知工具、越权写入和超预算的失败测试。
  2. 实现 Kahn 拓扑校验与 ready-set 计算；准备两个无依赖只读步骤，证明它们可并行，但共享预算只被原子扣减。
  3. 用 Spring AI 2.0.0 ChatClient.call().entity(CandidatePlan.class) 生成候选。让假模型依次返回 malformed JSON、循环计划和合法计划，证明只有最后一个能经业务 validator 产生 ExecutionPlan。
  4. 实现持久化 StepExecutor，在 RUNNING 之后、保存结果之前注入崩溃；用幂等键查证外部结果并恢复，不重复创建工单。
  5. 加入 MAX_REFLECTION_ROUNDS = 2、总 deadline、token、工具次数和成本预算；证明第 3 次反思、cost 不足或原子预占失败时，反思模型调用永远不会发生。
  6. 模拟人工拒绝与补偿失败，验证自动路径停止并生成包含 planVersion、步骤证据、残余影响和待决定问题的人工升级记录。

验收标准

  • 能用复杂度、不确定性、风险、延迟和成本解释为何选择固定工作流、单步循环、ReAct 或计划后执行，并明确反思只是有限增强层。
  • CandidatePlan 与 ExecutionPlan 分离；模型不能设置可信预算、授权、风险、审批、幂等键或补偿工具。
  • PlanValidator 在执行前拒绝环、缺失依赖、重复步骤、未知工具、本次 run 未公布工具、越权 / 不安全写入和按服务端估算超预算；全局授权不能替代 allowedToolNames membership。
  • StepExecutor 通过单事务 claimAndReserve 将 planVersion / fromStatus compare-and-set、attempt 递增与预算预占原子绑定；检查 AuthorizedAttempt 后才调用工具，并保存 idempotencyKey、Observation 摘要 / 外部引用与预算消耗。
  • 瞬时失败有限重试，不可重试失败直接停止；写结果未知先查证；补偿是独立获授权动作，失败时转人工。
  • 反思只由新可验证证据触发，最多 2 轮；每轮调用模型前通过 tryReserveReflection 原子预占 wall-clock、token、tool-call 和 cost，达到任一上限或预占竞争失败即升级且模型调用为 0。
  • Spring AI 仅承担模型交互和结构化候选转换；页面和实现均未宣称它原生提供 Planner、DAG validator、审批、工作流引擎、持久状态机、Executor 或 reflection loop。
  • 循环、缺失依赖、重复步骤、未知 / 越权工具、不安全写入、超时、不可重试失败、重试耗尽、反思超限、预算耗尽、部分完成、人工拒绝、崩溃恢复和版本冲突全部有自动化断言。
