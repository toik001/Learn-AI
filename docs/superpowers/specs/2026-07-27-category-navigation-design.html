知识库分类导航优化设计

日期：2026-07-27

目标

  • 学习页面左侧只展示当前 study-category 下的文档。
  • 侧栏固定保留知识库首页入口，并提供当前分类在首页中的锚点入口。
  • 知识库首页以大分类卡片作为第一层入口，同时保留分类文档列表和全库搜索。
  • 右侧页内目录统一结构；长标题自然换行，层级、活动项和移动端行为清晰。

信息架构

学习页面左侧

  1. 固定操作区：知识库首页。
  2. 分类摘要：当前分类名、文档数，以及指向首页对应分类区的链接。
  3. 当前分类文档列表：只包含同分类页面，当前文档用 aria-current="page" 标识。
  4. 分类内搜索：仅过滤当前分类文档。

知识库首页

  1. 英雄区和全库统计保持不变。
  2. 搜索区下方增加大分类入口网格；每张卡显示分类名、文档数、章节数和简短说明。
  3. 分类入口跳转至同页稳定锚点；锚点下继续展示该分类的全部文档卡。
  4. 搜索时分类入口卡保持可见，文档区按现有逻辑过滤。

右侧页内目录

  1. 生成器根据正文 h2～h4 统一生成 ol.toc-list。
  2. 每个条目带 toc-level-2～toc-level-4，沿用活动项观察逻辑。
  3. 链接使用 white-space: normal、overflow-wrap: anywhere 和合理行高。
  4. 目录容器独立滚动；窄屏继续隐藏右侧目录，不挤压正文。

实现边界

  • scripts/build-html-index.mjs 是导航和首页结构的唯一生成源。
  • public/assets/style.css 负责分类入口和目录可读性。
  • public/assets/app.js 只保留搜索、移动侧栏和目录高亮交互，不承担分类权限或结构过滤。
  • 分类依据页面元数据，不根据目录名或标题做启发式判断。

错误与退化处理

  • 分类为空时沿用现有 fallback 分类；生成器仍必须输出可用分类入口。
  • 正文没有 h2～h4 时输出“本页暂无分节”。
  • 已有目录标记不一致时统一替换整个 toc-sidebar，避免新旧结构并存。
  • 若页面不存在左右侧栏容器，生成器不猜测布局，只更新可识别区域。

验收与测试

  • 每篇文档的左侧文档集合恰好等于当前分类集合，且只有一个活动项。
  • 每篇文档可一跳返回知识库首页，并可跳到当前分类首页锚点。
  • 首页大分类卡数量等于 manifest 中唯一分类数，链接锚点存在。
  • 所有右侧目录使用统一列表结构，链接目标存在且长标题具备换行规则。
  • 桌面与移动端无水平溢出；索引生成连续运行两次除时间戳外不产生变化。
