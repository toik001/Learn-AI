GitHub Pages 迁移设计

目标

把 Learn-AI 知识库从自建 GitLab Pages 完整迁移到 GitHub Pages，同时保留 public/ 作为唯一静态网站根目录，确保项目站点可部署在 https://toik001.github.io/Learn-AI/ 子路径下，并用自动校验阻止失效链接、错误锚点或未同步索引进入部署。

方案选择

  1. GitHub Actions 上传 public/ artifact：采用。无需移动内容目录，能够在部署前运行确定性校验，并使用 GitHub Pages 官方 OIDC 部署链路。
  2. 从 main 的仓库根目录或 docs/ 直接发布：会破坏现有 public/ 内容边界，且难以在发布前执行完整校验，不采用。
  3. 维护独立 gh-pages 分支：会产生第二份生成物状态和额外同步流程，不采用。

发布架构

  1. 向 main 推送提交，或在 Actions 页面手动触发工作流。
  2. build job 检出仓库，固定 Node.js 24，运行站点语法、内容回归、索引一致性和链接锚点校验。
  3. 校验通过后，actions/upload-pages-artifact 只打包 public/，仓库规则、脚本和工作流不会进入公开站点。
  4. deploy job 依赖 build，使用 pages: write 和 id-token: write 权限，把 artifact 部署到 github-pages environment。
  5. 工作流通过 concurrency 串行化 Pages 发布；保留正在进行的生产部署，并由 GitHub 合并中间排队运行，最终继续发布最新提交。

项目结构调整

  • 删除 .gitlab-ci.yml。
  • 新增 .github/workflows/pages.yml，只从 main 发布，也支持 workflow_dispatch。
  • 新增 scripts/verify-site.mjs，验证本地 HTML 链接、资源、片段锚点、重复 ID、根路径引用、知识页元数据和外链安全属性。
  • 新增 scripts/test-verify-site.mjs，用临时站点证明校验器能接受有效页面并拒绝失效链接、未知锚点、根路径引用、重复 ID 和不安全外链。
  • 更新 AGENTS.md，将结构、发布规则和提交前校验切换为 GitHub Pages。
  • 新增根目录 README.md，说明知识库入口、目录结构、本地使用、内容维护、完整校验、GitHub Pages 启用方式和默认线上地址。该文件是用户明确要求的 Markdown 例外。
  • 把项目专属的 GitLab Pages 页面重命名并重写为 GitHub Pages 指南；其他讨论 GitLab 的通用学习页面保持不变。
  • 运行索引生成器，刷新 public/index.html、各页面分类导航、上一篇/下一篇和 public/manifest.json。

路径与内容边界

  • 所有站内链接和资源继续使用相对 URL，不硬编码 /Learn-AI/，因此同一份 public/ 可本地打开、部署到项目子路径或未来绑定自定义域名。
  • CI 不生成或修复知识内容。它可以在临时副本中运行索引生成器并比较结果，但发布的始终是提交中已经存在且通过一致性检查的 public/。
  • 不创建 Jekyll 配置，不维护 gh-pages 分支，不把内部工程文件复制到 public/。
  • 仓库外部只需要一次性在 GitHub Settings → Pages → Source 选择 GitHub Actions；自定义域名不在本次范围内。

错误处理与验证

  • 任一脚本、内容回归、链接、锚点或索引一致性检查失败时，build job 失败且不产生可部署 artifact。
  • deploy job 通过 needs: build 保证不会搜索不存在或未校验的 artifact。
  • 工作流显式提供 environment.url，部署完成后在 GitHub 环境记录中展示实际 Pages 地址。
  • 本地验收覆盖所有 scripts/test-*.mjs、Node.js 语法、索引幂等、站点完整性、YAML 结构、git diff --check 和干净工作区检查。
