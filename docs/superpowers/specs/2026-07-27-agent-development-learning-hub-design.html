Agent 开发主学习目录设计规格

确认日期：2026-07-27

目标与范围

在现有 Java 全栈 AI 学习库中新建一个厂商无关的 Agent 开发主入口， 帮助有 Java、Spring Boot 背景的开发者先建立 AI Agent 的通用心智模型， 再按学习路线进入 Tool Calling、记忆、RAG、规划、多 Agent、评测、安全和部署等专题。

首页不绑定某个模型或 Agent 框架。Codex、Spring AI、LangChain4j 等产品与框架 只作为概念映射或后续专题，不作为 Agent 定义本身。

读者与成功标准

目标读者是熟悉 Java Web 开发，但尚未系统学习 AI Agent 的开发者。

  • 读者能用自己的话解释 Agent 与聊天机器人、固定工作流的差异。
  • 读者能说出 Agent 一次调用中目标、模型、工具、状态和反馈循环的作用。
  • 读者能将 Agent 的核心组件映射到常见 Java 分层与工程实践。
  • 读者能按照页面中的路线选择下一阶段学习主题。
  • 读者能理解并开始实现一个调用受控工具的最小 Java Agent。

页面信息架构

  1. 核心结论：用简洁定义建立页面主旨。
  2. 通用释义：区分 Software Agent、AI Agent、LLM Agent 和 Agentic System。
  3. 边界辨析：比较聊天机器人、固定工作流、Agent 和多 Agent 系统。
  4. 核心组成：解释目标、模型、指令、工具、知识、记忆、状态、规划、护栏与人工审批。
  5. 调用过程：通过主流程图和逐步说明解释一次完整调用。
  6. Java 映射：将 Agent 组件映射到 Spring Boot 常见架构。
  7. 最小代码：提供 Java 21 的厂商无关伪代码，展示工具调用循环。
  8. 学习路线：建立从基础到生产的八阶段主目录。
  9. 实践与验收：给出最小天气工具 Agent 练习及完成标准。
  10. 参考资料：列出用于定义、调用模型和 Java 映射的一手资料。

流程图设计

使用语义化 HTML 与共享 CSS 绘制响应式流程图，不使用装饰性图片或内联 SVG。 桌面端按主调用链横向或分段排列，窄屏按步骤纵向重排。

主链为：用户目标 → 上下文组装 → 模型决策 → 工具调用 → 环境反馈 → 状态更新 → 循环判断 → 最终响应。

权限校验、参数校验、人工确认、超时、重试上限和失败降级作为跨步骤护栏显示， 防止流程图造成“Agent 可以无限自主运行”的误解。流程图同时提供文字版说明， 以满足屏幕阅读器和无法显示复杂布局时的可访问性要求。

Java 映射与代码边界

  • Agent Runtime 对应应用服务与编排层。
  • Tool 对应受控的 Service、Gateway 或 Adapter，而不是允许模型执行任意代码。
  • Memory 对应会话状态、短期上下文和持久化存储。
  • Knowledge/RAG 对应检索服务及其数据源。
  • Guardrail 对应参数校验、鉴权、业务规则、限流和输出校验。
  • Observation Loop 对应有预算和终止条件的状态循环，不等同于普通单次 Controller 调用。

示例使用 Java 21 语法，只定义必要接口与循环控制，不引入厂商 SDK， 从而保证概念可迁移到 Spring AI、LangChain4j 或直接模型 API。

主学习路线

  1. Agent 基础概念与边界。
  2. 模型 API、结构化输出与 Tool Calling。
  3. 状态、上下文与记忆。
  4. 知识检索与 RAG。
  5. 规划、反思与任务分解。
  6. 多 Agent 协作与编排。
  7. 评测、安全、权限与成本控制。
  8. Java 生产部署、可观测性与故障恢复。

当前主入口为每个阶段提供学习目标、关键问题、实践任务和验收标准。 尚未创建的子专题显示为“待建设”，不生成失效链接。
