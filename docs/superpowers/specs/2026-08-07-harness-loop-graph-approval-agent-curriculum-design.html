Harness、Loop、Graph 的运行时 Agent 与编码 Agent 四篇课程设计

目标

把 Harness、Loop、Graph 从容易混淆的术语拆成三篇可独立阅读的学习页，再用一篇整合页展示两种不同的使用视角：一是开发并运行企业智能审批 Agent，二是在 Codex、Claude Code 等编码 Agent 中使用这些概念开发软件项目。读者以 Java 全栈开发者为主；课程同时解释原理、项目开发方法和生产上线约束，而不只罗列框架 API。

采用的内容方案

采用“递进课程 + 两类项目示例 + 审批 Agent 双轨实现”。Harness、Loop、Graph 三篇分别建立概念边界，并在每篇中并列展示两种实践：

  1. 智能审批 Agent 开发：再分为无 Agent 框架与 Spring AI 两条实现轨道。无框架轨道使用 Java 25、Spring Boot、普通接口与状态机展示最小机制；Spring AI 轨道使用官方能力完成模型调用、工具调用、结构化输出、顾问链和可观测性集成。
  2. 代码开发过程中的使用：用 Codex 与 Claude Code 的仓库指令、工具/权限、任务循环、测试反馈、计划门禁、子任务和审查流程解释 Harness、Loop、Graph 如何帮助开发普通软件项目。

不采用纯框架教程，因为它会把 Harness、Loop、Graph 错误等同于特定 API；也不把 Codex/Claude Code 的每个功能强行称为 Graph。文档会区分产品官方术语与本文用于分析软件开发流程的概念映射。

四篇页面边界

  1. Harness：解释模型外围的上下文、工具、权限、沙箱、结构化契约、测试、评测、日志、指标、Trace、恢复和安全护栏。审批部分聚焦“让提案 Agent 在受控环境中可靠工作”；编码部分聚焦仓库指令、MCP/工具、权限、worktree、测试、CI 与可观测反馈怎样形成 Codex/Claude Code 的开发跑道。
  2. Loop：解释 Observe–Decide–Act–Verify、成功/预算/升级三类停止、重试与退避、幂等、上下文压缩、失败分类和人工接管。审批部分聚焦“材料缺失—补件—重试—升级”；编码部分聚焦“理解需求—检查仓库—修改—测试—审查—修复”的工具反馈循环、TDD 循环和停止条件。
  3. Graph：解释 State、Node、Edge、Router、Checkpoint、并行汇聚、循环边与人工节点，区分确定性工作流图和模型动态拆分。审批部分聚焦“收件—并行核验—规则路由—会签—执行”；编码部分聚焦“规格—计划—任务—实现—审查—验证—交付”的阶段图、任务依赖和多 Agent 协作，并明确这可能是工程流程图而非产品内置 Graph 引擎。
  4. 整合使用：采用双层案例。第一部分完整开发并运行企业智能审批 Agent；第二部分展示怎样用 Codex/Claude Code 按 Harness、Loop、Graph 方法开发这个审批项目。读者既看到运行时 Agent 架构，也看到编码 Agent 如何构建、测试和交付该架构。

项目开发方法

审批 Agent 开发：

  1. 先识别必须确定性的业务规则、风险等级和人工审批点，再决定哪里允许模型参与。
  2. 先实现无框架版本的领域接口、状态、工具边界和验收测试，再接入 Spring AI 适配器。
  3. 将提示、模型、工具和策略版本化；将审批事实、证据与执行记录持久化，不把聊天历史当业务数据库。
  4. 用契约测试、场景测试、离线评测、对抗测试和线上观测覆盖正确性、安全、成本与恢复能力。
  5. 按 shadow、辅助决策、低风险自动化三个阶段上线，高风险写操作始终要求授权和幂等保护。

使用编码 Agent 开发项目：

  1. 先建设 Agent 可读仓库：入口规则只做地图，详细架构和运行手册保持版本化，并提供一条命令完成常用验证。
  2. 把需求写成目标、范围、约束、完成定义和验证命令；让 Codex/Claude Code 先检查现实状态，再提出计划。
  3. 让每个实现任务在小 Loop 中完成，使用新鲜测试输出证明结果；独立任务才并行，存在共享状态时显式串行。
  4. 用阶段门禁组织 Graph：规格确认、计划确认、实现、审查、验证、人工决策和交付，不用自由循环替代授权。
  5. 把失败归因并反馈到 Harness、Loop 或 Graph 的正确层，而不是只追加提示词或盲目重试。

代码与框架边界

  • 审批 Agent 示例使用 Java 25、Spring Boot 与 Maven；示例保持可迁移，不承诺仓库内生成完整可运行产品。
  • 无框架轨道展示 ModelClient、Tool、AgentState、LoopRunner、ApprovalGraph 等普通 Java 抽象。
  • Spring AI 轨道映射到 ChatClient、结构化实体映射、@Tool/ToolCallback、Advisor、Observation 与模型可替换配置。
  • Spring AI 不拥有审批业务状态、最终授权和外部系统副作用；这些由数据库、规则组件、工作流/应用服务和受限执行器负责。
  • 不引入另一套 Agent 框架作为主实现；LangGraph、OpenAI Agents SDK 等只用于官方概念或行业实现对照。
  • 代码开发示例以 Codex 和 Claude Code 为主要产品映射，所有功能名称、配置文件、权限、Hook、子 Agent 或并行能力均以各自官方文档为准；无法一一对应时明确标注为本文的工程抽象。
