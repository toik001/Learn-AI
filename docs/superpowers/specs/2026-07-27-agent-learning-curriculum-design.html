Agent 开发八阶段学习课程设计规格

确认日期：2026-07-27

目标与范围

将 Agent 开发主学习目录中的八个“待建设”阶段全部建设为独立 HTML 学习页， 形成面向 Java 全栈开发者的连续课程。每篇既可单独查阅，又沿用同一个共享案例， 使前一阶段的设计产物成为后一阶段的输入。

课程保持厂商无关的 Agent 心智模型，同时增加 Spring AI 工程示例。 页面必须明确区分 Spring AI 原生能力与需要业务代码自行实现的运行时、状态机、 权限、审批、评测、多 Agent 编排和故障恢复能力。

读者与完成标准

目标读者熟悉 Java、Spring Boot 和常规后端开发，但尚未系统建设生产级 Agent。

  • 八个阶段均有独立页面，主目录不再出现“待建设”。
  • 读者可以按顺序完成从 Agent 边界设计到生产部署的完整学习闭环。
  • 每篇同时说明通用原理、Java 21 表达方式和对应的 Spring AI 落地方式。
  • 所有写操作、外部调用、记忆、检索和多 Agent 协作都具有明确安全边界。
  • 最后一篇能够将前七篇产物组合成可观测、可恢复的 Spring Boot Agent 服务设计。

课程组织方式

采用“渐进课程 + 共享案例”，不采用八篇互不相关的百科，也不合并为单篇超长教程。

共享案例为“企业服务台 Agent”：查询服务状态和用户工单，从内部知识库检索故障处理规则， 分解诊断任务，在人工审批后创建工单；后续扩展为多 Agent，并加入评测、安全、成本和生产运维。

主目录现有的天气工具 Agent 保留为最小入门练习；八阶段课程使用企业服务台案例， 以支持状态、RAG、规划、多 Agent 和生产治理等连续演进。

双层示例约定

  1. 原理层：使用 Java 21 的 interface、record、sealed interface、状态对象和服务边界， 表达与模型厂商、SDK 和框架无关的设计。
  2. 工程层：使用检索时核验的 Spring AI 当前官方 API， 展示 Spring Boot 中的 ChatClient、Advisor、Tool Calling、Chat Memory、RAG、 Observability 和测试接入方式。

Spring AI 示例不得把框架未提供的能力描述成原生功能。Planner、Coordinator、审批、 状态恢复、策略引擎和恢复队列等由业务 Bean 或基础设施实现时，必须显式标注。

八篇专题页面

1. Agent 基础概念与边界

建立目标、环境、状态、工具、模型、护栏和人工协作模型；比较聊天、固定工作流、 Agent 与 Agentic System；通过企业服务台需求完成四栏设计，并给出不应使用 Agent 的判断树。 Spring AI 示例说明 ChatClient、Advisor、工具和业务 Agent Runtime 的职责边界。

2. 模型 API、结构化输出与 Tool Calling

解释结构化输出、JSON Schema、互斥决策分支、参数校验、工具白名单、超时和安全失败信息。 Java 示例使用 sealed interface 与 record；Spring AI 示例使用官方 Tool Calling API， 展示服务状态查询和工单查询工具。

3. 状态、上下文与记忆

区分运行状态、提示上下文、短期会话记忆和长期业务记忆；覆盖序列化、恢复、脱敏、 保留期限和会话隔离。Spring AI 示例使用官方 Chat Memory 能力，同时说明业务状态不能只存于聊天消息。

4. 知识检索与 RAG

覆盖文档采集、切分、元数据、嵌入、召回、过滤、重排、引用、检索评测和诚实降级。 Spring AI 示例使用官方 Document、ETL、VectorStore 和检索 Advisor/API， 为服务台知识答案保留来源。

5. 规划、反思与任务分解

比较固定流程、动态计划、ReAct 和反思循环，解释何时规划有价值、何时只增加成本。 Java 与 Spring 示例使用显式 Planner、Executor、StepState Bean 和预算， 不虚构 Spring AI 自带通用规划器。

6. 多 Agent 协作与编排

比较单 Agent、主管—执行者、流水线和并行拓扑，讨论角色工具隔离、共享状态版本、 冲突和失败传播。Spring AI 示例使用多个专用 ChatClient/服务 Bean 与显式 Coordinator， 并与单 Agent 基线比较。

7. 评测、安全、权限与成本控制

建立离线数据集、结果评测、轨迹评测、策略门、审批、审计、提示注入防护、token 和工具预算。 Spring AI 示例使用 Advisor、工具策略、Micrometer/Observability 和 Spring 测试， 覆盖越权、超时、超预算及工具故障。

8. Java 生产部署、可观测性与故障恢复

形成 Spring Boot API、同步/异步执行边界、日志、指标、Trace、幂等、重试、 熔断、恢复队列和安全重放方案。示例组合 Spring AI Observability、 Spring Boot Actuator、Micrometer/OpenTelemetry 和业务恢复机制。

每篇统一结构

  1. 核心结论、学习目标、前置知识和本阶段产物。
  2. 直观理解、核心原理、概念边界和选择建议。
  3. 至少一张由语义化 HTML/CSS 构成的流程图、状态图或架构图，并提供等价文字说明。
  4. 厂商无关的 Java 21 核心模型或伪代码。
  5. Spring AI 当前官方 API 示例、依赖说明和能力边界。
  6. 企业服务台案例在本阶段新增的组件、状态或约束。
  7. 常见错误、安全注意事项、练习和可验证的验收标准。
  8. 相关专题、上一篇/下一篇及一手参考资料。

资料检索与事实边界

  • Spring AI 的版本、BOM、Spring Boot 兼容性、类型和方法以 2026-07-27 官方文档为准。
  • Agent 方法使用论文原文、标准组织、官方项目文档和源代码仓库交叉核验。
  • 论文结论、框架能力、工程建议和推测必须明确区分。
  • 每篇参考资料记录检索日期，正文关键结论尽量就近链接来源。
  • 无法由官方资料确认的 API 不进入代码示例；存在版本差异时明确标注。

安全与错误处理

  • 模型只提出工具请求，应用负责鉴权、校验、审批和执行。
  • 外部文本、检索文档和工具 Observation 均视为不可信输入。
  • 公开错误信息与私有诊断分离，不向用户泄露原始异常、密钥、内部 URL 或工具输出。
  • 写操作必须说明幂等、审批、审计和补偿策略。
  • 循环、并发、token、时间和工具调用都有明确预算和终止条件。

验证要求

  • 八个页面均包含必需元数据、header、main、article、nav、核心结论和参考资料。
  • 每篇的目录锚点唯一且可命中，站内链接使用相对路径，外链使用安全属性。
  • Java/Spring 代码中的 HTML 特殊字符正确转义，类型和方法与引用的官方版本一致。
  • 每篇至少包含一项 Java 21 示例、一项 Spring AI 示例、一项练习和明确验收标准。
  • 主目录八个专题链接全部存在，状态不再是“待建设”。
  • 运行索引脚本后知识文档数为 17，并更新首页、侧栏、上一篇/下一篇和 manifest。
  • 脚本语法、重复 ID、本地链接、标题锚点和外部链接属性检查全部通过。
