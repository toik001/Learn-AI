Codex 官方原生项目开发最佳路径设计

日期：2026-07-28

目标

为不使用 AIDLC、OpenSpec、Superpowers 或其他附加工作流的开发者，提供一条只依赖 Codex 官方能力、Git 和项目自身构建测试命令的端到端开发路径。

方案选择

采用“统一默认闭环 + 表面映射 + Java 项目模板”。统一闭环回答每一步做什么，表面映射说明 CLI、IDE 扩展与桌面 App 如何执行同一步，Java 模板让读者可以直接在 Spring Boot 项目使用。按产品表面分别讲会造成重复；以团队成熟度为主线则不够操作化。

范围边界

  • 包含：Codex CLI、IDE 扩展、ChatGPT 桌面 App 中的 Codex、Codex worktree、Plan mode、AGENTS.md、sandbox/approval、/diff、/review、Git 提交与 PR。
  • 包含：项目已有的 Maven、Gradle、npm、测试、lint、构建、浏览器和 CI 命令。
  • 不依赖：AIDLC、OpenSpec、Superpowers、第三方工作流、外部 Skill、MCP 或自动化平台。
  • Skills、MCP、hooks、scheduled tasks 只在结尾作为“重复摩擦出现后再考虑”的可选升级，不进入默认路径。
  • 所有“官方明确建议”与“本文综合出的推荐顺序”分开标识，避免把综合判断伪装成官方固定流程。

核心路径

  1. 从正确 Git 根目录启动 Codex，检查分支、工作区和项目可运行性。
  2. 建立最小仓库说明：启动、构建、快速测试、完整测试、禁止事项。
  3. 使用 /init 生成并精简 AGENTS.md，只保存持久规则。
  4. 根据风险选择 Local 或 worktree；保持默认 sandbox 和 approval，仅按需扩大权限。
  5. 每个可独立验收的结果使用一个 chat，不让单个 chat 承载整个项目生命周期。
  6. 提示词包含 Goal、Context、Constraints、Done when；小任务直接执行，复杂任务先进入 Plan mode。
  7. 先检查与复现当前行为，再做最小范围实现；让 Codex 读取差异并持续报告进度。
  8. 按“最小相关检查 → 模块/集成检查 → 全量/真实运行”逐层验证。
  9. 使用 /diff 检查范围，使用 /review 建立第二视角；修复后重跑检查与 review。
  10. 人工检查关键业务和高风险动作，再 stage、commit、push、创建 PR。
  11. 任务结束后只把重复出现的摩擦沉淀进 AGENTS.md 或稳定脚本。

页面结构

  1. 核心结论和“官方原生”边界。
  2. 十一阶段闭环图与文字替代。
  3. 任务规模决策表：局部修改、Bug、跨模块需求、UI、迁移与高风险变更。
  4. 阶段详解：目标、推荐动作、验证证据、停止条件和常见错误。
  5. CLI、IDE、桌面 App 能力映射表。
  6. Java 21 + Spring Boot 项目 AGENTS.md 最小模板。
  7. 功能开发、Bug 修复和代码审查三套提示词模板。
  8. 验证金字塔、权限基线、交付清单和反模式。
  9. 官方资料和检索日期。
