GitHub Pages 迁移实施计划

Agent 执行要求：使用 superpowers:executing-plans 在当前会话按任务执行；功能脚本使用 superpowers:test-driven-development 完成红—绿循环。

目标：将 Learn-AI 从 GitLab Pages 迁移到 GitHub Pages，通过 GitHub Actions 校验并发布已提交的 public/，同时提供完整 README、项目规则和部署学习页。

架构：build job 运行 Node.js 校验并上传唯一 Pages artifact，deploy job 以最小权限发布到 github-pages environment。站点保持相对链接和 public/ 内容边界，索引生成仍由本地维护流程负责。

技术栈：纯静态 HTML/CSS/JavaScript、Node.js 24、GitHub Actions、GitHub Pages 官方 actions。

全局约束

  • 发布目录固定为 public/，默认项目站点地址为 https://toik001.github.io/Learn-AI/。
  • 所有站内链接和资源必须使用相对 URL，不硬编码仓库子路径。
  • 工作流只从 main 自动发布，并支持 workflow_dispatch。
  • 发布 action 固定为 2026-07-29 官方仓库最新主版本：actions/checkout@v6、actions/setup-node@v6、actions/configure-pages@v6、actions/upload-pages-artifact@v5 和 actions/deploy-pages@v5。
  • 部署 job 只增加 pages: write 和 id-token: write，目标 environment 固定为 github-pages。
  • 除用户明确要求的根目录 README.md 和控制文件 AGENTS.md 外，不新增 Markdown 内容。
  • 其他通用 GitLab 教程保持不变；只删除 GitLab CI 并迁移项目专属 Pages 页面。

任务一：以 TDD 建立站点完整性校验器

新建：scripts/test-verify-site.mjs、scripts/verify-site.mjs。

接口：node scripts/verify-site.mjs [--root <目录>]；默认扫描 public/，成功输出文件统计并以 0 退出，发现问题逐行输出相对文件、规则和目标后以 1 退出。

  1. 先编写测试夹具：有效站点必须通过；缺失本地文件、未知片段锚点、根路径引用、重复 ID、不安全外链分别必须失败并包含对应诊断文本。
  2. 运行 node scripts/test-verify-site.mjs，确认因 scripts/verify-site.mjs 不存在而失败。
  3. 实现递归收集 HTML/CSS/JS、HTML 属性解析、实体与 URL 解码、本地路径越界防护、目标存在性、HTML 片段、重复 ID、知识页元数据、语义标签和外链 target/rel 校验。
  4. 运行 node scripts/test-verify-site.mjs，确认全部夹具通过；再运行 node scripts/verify-site.mjs 检查真实站点并修复校验器兼容性问题，不放宽既有项目规则。
  5. 提交 test: add static site integrity verification。
