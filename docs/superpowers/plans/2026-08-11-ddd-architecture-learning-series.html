DDD 架构七篇学习专题实施计划

供执行者：按任务逐项实施；执行时必须使用 superpowers:executing-plans，或在用户明确要求多代理执行时使用 superpowers:subagent-driven-development。每个步骤用复选项跟踪。

目标：发布一套面向 Java 开发者的七篇 DDD 架构专题，以订单领域贯穿基础概念、战略设计、战术设计、分层方式、Java 实践与演进决策。

架构：七篇语义化 HTML 写入独立的“软件架构与 DDD”分类，通过专题导航和现有全站生成器互联。精确标注的本地 SVG 负责主要图解，Node.js 契约测试负责页面职责、图片、互链和来源结构，现有站点验证器负责通用 HTML 契约。

技术栈：HTML5、SVG 1.1/2、现有 CSS 与原生 JavaScript、Node.js 24 测试脚本、Java 21 与 Spring Boot 工程语境。

全局约束

  • 恰好创建七篇页面，日期固定为 2026-08-11，分类固定为“软件架构与 DDD”。
  • Java 示例固定使用 Java 21；领域模型不得依赖 Spring、JPA 或 Web 类型。
  • 七篇每篇至少一个 <figure>，合计至少九张本地 SVG；每张图片具有非空 alt、<figcaption> 和正文等价说明。
  • 资料检索截面为 2026-08-11；优先使用原作者、模式作者、官方文档与权威架构资料，关键结论在正文附近标注来源。
  • 每页包含“核心结论”和“参考资料”、稳定唯一标题 ID、专题导航及至少一个 Java 对照、练习或验收项。
  • 站内资源使用相对路径；所有外链包含 target="_blank" 与 rel="noopener noreferrer"。
  • 不创建 Markdown 学习笔记，不创建独立 Spring Boot 工程，不引入前端依赖，不复制外部受版权保护图片。

代码接口：Money 为带币种且拒绝负数的值对象；Order 聚合通过行为方法维护订单项与状态不变量；CreateOrderUseCase 依赖 OrderRepository 端口；OrderCreated 记录订单 ID 和发生时间；适配器实现端口但不向领域泄露 JPA Entity。

public record Money(BigDecimal amount, Currency currency) {
    public Money {
        Objects.requireNonNull(amount, "amount");
        Objects.requireNonNull(currency, "currency");
        if (amount.signum() < 0) throw new IllegalArgumentException("amount must be non-negative");
    }
}

public interface OrderRepository {
    Optional<Order> findById(OrderId id);
    void save(Order order);
}

public record OrderCreated(OrderId orderId, Instant occurredAt) {}
